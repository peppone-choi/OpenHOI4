## 0. 표기 규약

세 문서는 같은 식별자와 용어를 쓴다. 식별자를 바꾸거나 지우지 않는다. 폐기된 항목은 행을 남기고 `폐기`로 표시한다.

| 식별자 | 의미 | 정의 위치 |
|---|---|---|
| `D-NN` | 프로젝트 결정 사항 (정체성·범위·기술·라이선스) | 01 §2 |
| `REQ-영역-NN` | 요구사항 | 01 §8 |
| `OPEN-NN` | 아직 정하지 않은 게임 규칙 | 01 §9 |
| `M0`~`M6` | 마일스톤 | 01 §10 |
| `AC-M#-NN` | 마일스톤 완료 기준 | 01 §10 |
| `WP-NN` | 작업 패키지 | 02 §12 |
| `DR-NN` | 결정론 규칙 | 02 §3 |
| `P-NN` | 제작용 프롬프트 | 03 |

**상태 표기**

- `확정` — 사용자가 확인했다.
- `잠정` — 사용자 확인 전 기본값이다. 이 값으로 구현해도 된다. 바뀔 수 있으므로 하드코딩하지 않고 데이터나 설정으로 둔다.
- `미결정` — 구현하지 않는다. 인터페이스 자리만 두고, 결정 요청 절차(03 P-10)를 따른다.

**요구사항 우선순위**

- `필수` — 해당 마일스톤 완료의 조건이다.
- `권장` — 해당 마일스톤에 넣는 것이 좋다. 빠져도 완료를 막지 않는다.
- `후순위` — 해당 마일스톤 이후에 다시 계획한다.

**검증 방법 코드** (요구사항 표의 `검증` 열)

## 1. 한 줄 정의와 목표

**OpenHOI는 1930~40년대 세계대전을 다루는, 웹 브라우저에서 플레이하는 실시간(일시정지 가능) 대전략 게임이다. 동시에 그 게임을 어떤 시대·세계관으로도 바꿀 수 있는 오픈소스 엔진이다.**

> 플레이어는 기존 HOI 대신 OpenHOI를 선택한다. 무료 오픈소스이고, 화면의 모든 수치가 어디서 왔는지 추적되며, 시대와 세계관을 통째로 바꾸는 모드를 엔진 차원에서 지원하기 때문이다.

### 1.1 목표

1. 국가 하나를 맡아 세계가 동시에 움직이는 실시간 대전략 경험을 제공한다. 평시 준비부터 전쟁, 항복, 강화까지 이어진다.
2. 엔진과 콘텐츠를 분리한다. 기본 게임도 하나의 데이터 팩으로 동작한다.
3. 모든 파생 수치를 투명하게 보여준다(수치 원장). 규칙을 문서와 툴팁으로 공개한다.
4. 결정론적 시뮬레이션으로 만든다. 그래서 저장·재현·멀티플레이·AI 평가를 같은 기반 위에서 처리한다.
5. 원작의 저작물을 쓰지 않고 독립적으로 만든다(클린룸, §7).

### 1.2 대상 플레이어

| 대상 | 원하는 것 | OpenHOI가 주는 것 |
|---|---|---|
| 대전략 게임 애호가 | 무료이고 수정 가능한 대안 | 오픈소스, 투명한 규칙 |
| 대체역사·시나리오 모드 제작자 | 시대·이념·장비·지도를 코드 수정 없이 교체 | 시대 독립 엔진, 데이터 팩, 검증기, 자동 생성되는 데이터 레퍼런스 |
| 시스템 분석형 플레이어·연구자 | 수치의 근거 | 수치 원장, 헤드리스 CLI, 재현 가능한 실행 |

### 1.3 비목표

- 특정 원작 버전을 수치까지 그대로 복제하는 것. 법적 위험이 있고(§7) 개선 목표와도 충돌한다.
- 원작 설치 파일이나 기존 원작 모드를 읽어 실행하는 것(D-09).
- 3D 지형 표현, 사실적 그래픽.
- 네이티브 데스크톱 클라이언트. 클라이언트는 웹이다(D-07).

## 3. 핵심 플레이 흐름

```
국가 선택 → 평시 준비 → 위기 고조 → 전쟁 → 결과 → (다음 국면)
            │            │            │        │
            │            │            │        └ 항복·강화, 영토 변경, 진영 재편
            │            │            └ 편제·전선·공세 계획·보급·전투
            │            └ 국제 긴장도 상승, 명분 생성, 진영 가입
            └ 의제·연구·건설·생산·법령·외교
```

### 3.1 시간 흐름

- 시뮬레이션은 **틱** 단위로 진행한다. 1틱은 게임 내 1시간이다.
- 일시정지와 5단계 속도가 있다. 속도별 실시간 비율은 데이터 값이다.
- 처리 주기는 세 가지다. 매 틱(명령·이동·전투), 매 게임일 0시(경제·정치·AI 등), 매월 1일(통계). 순서는 02 §6.2에 고정한다.

### 3.2 플레이어가 하는 일

| 국면 | 주요 행동 | 관련 시스템 |
|---|---|---|
| 평시 | 의제 선택, 연구 배정, 산업 역량 배분, 건설 지시, 생산 라인 설정, 법령 변경, 외교 행동 | NAT·ECO·TEC·AGD·DIP |
| 위기 | 명분 생성, 진영 가입·창설, 보장, 동원 법령 강화, 편제 설계, 사단 훈련 | DIP·MIL |
| 전쟁 | 군 편성, 전선 할당, 공세 계획 설정, 사단 직접 이동, 보급 거점·철도 건설, 보충 우선순위 | MIL·CMB·SUP |
| 결과 | 항복 처리, 강화 조건, 점령지 관리 | DIP·ECO |

### 3.3 승패

- 시나리오마다 종료 조건이 데이터로 정의된다(REQ-TIME-04).
- 플레이어 국가가 항복하면 게임이 끝난다. 계속 관전할지는 선택이다.
- 종료일에 도달하면 결과 화면에 점수를 보여준다. 점수는 보유 승점, 산업 역량, 생존 여부, 진영 승리 여부의 가중합이고 가중치는 데이터 값이다.

WP-13의 REQUEST-0009 A (기술 범위: [공개 인계 기술 메모](technical-notes.md))는 2026-10-07 CEO 한정 잠정 채택이다. `end_date`는 마지막 플레이 가능 날짜이며 다음날 00:00에 도달하는 성공 step에서 종료한다. start=end는 하루, end<start는 로드 오류다. 종료 조건은 명시 단일 AST/all·any·not이며 국가 조건의 root를 명시한다. 초기 권위 생성 뒤 한 번, 이후 성공 시간전진 step의 시스템·원장 뒤 평가한다. 초기 참은 tick0 종료이고 조건은 부작용이 없다. 날짜·조건·명시 종료 효과의 typed 원인은 안정 순서로 함께 보존하며 효과 목록 전체 성공 후만 commit한다.

종료 checkpoint 이후 step·새 gameplay/Pause/Speed enqueue는 거부하고 기존 future queue·state·clock을 보존한다. 조회·결과 확인·저장은 허용한다. nation-scope 허용 ID 플래그는 명시 root/국가 scope로 분리하며 실행 수명 동안 set/clear로만 바뀐다. 중복 set/없는 키 clear는 idempotent이고 전체 효과 실패는 flags·종료 후보·RNG·queue까지 rollback한다. 기존 예정 명령 의미오류 소비와 phase 오류 전체 rollback은 구분해 유지한다. 이 잠정은 사용자 D/OPEN 확정이 아니다. unsupported scope·primitive·nonzero 점수축 사용은 실제 host capability 로드 오류이며 가짜 0/false/no-op으로 성공시키지 않는다. 네 점수축·결과화면 및 항복 뒤 관전 선택 요구는 후속 실제 producer까지 유지한다. 원 M0/M1 None 모드와 v1/v2/v3 bytes·hash·fixture를 보존하고 새 정의가 empty 값이어도 additive 상태/저장형에 정의 신원을 남긴다.

## 4. 시스템 규칙

여기 적은 규칙은 **구조**다. 수치 상수는 모두 데이터 팩의 `defines`에 둔다. 아래에 나오는 예시 수치는 잠정 기본값이다. 원작 수치를 옮겨 오지 않는다(§7).

### 4.1 지도 (MAP)

- **프로빈스**: 지도의 최소 단위다. 종류는 육지·바다·호수다. 지형 종류와 지형별 이동·전투 보정은 데이터로 정한다.
- **인접**: 프로빈스 비트맵에서 자동으로 생성한다. 하천(소·대), 해협 횡단, 통행 불가는 덮어쓰기 테이블로 지정한다.
- **주**: 육지 프로빈스를 묶은 행정 단위다. 인구, 전략 자원 산출, 건물, 인프라 수준을 가진다. 육지 프로빈스는 정확히 한 주에 속한다.
- **해역·공역**: 바다 프로빈스를 묶은 해역과, 육지·바다를 묶은 공역이다. 해군·공군 추상화(M4)에 쓴다.
- **소유와 통제**: 소유는 법적 귀속, 통제는 군사적 점령이다. 둘을 구분한다.
- **승점(VP)**: 일부 프로빈스에 부여한다. 항복 진행도와 점수에 쓴다.

### 4.2 국가와 정치 (NAT)

- **국가**: 식별자(태그), 이름, 색, 수도, 정부 형태, 이념별 지지율, 지도자를 가진다.
- **정치 자본(PC)**: 매일 얻는다. 법령 변경, 결의, 명분 생성, 외교 행동에 쓴다.
- **안정도**와 **동원도**: 0~100%다.
  - 안정도는 생산 효율, 항복 진행도 보정, 일부 행동 조건에 영향을 준다.
  - 동원도는 징병·경제 법령의 상한 조건, 공세 시 조직력 보정, 전쟁 피로 저항에 영향을 준다.
- **법령**: 범주(징병·경제·무역 등)와 단계를 데이터로 정의한다. 변경하려면 PC를 쓰고 조건을 충족해야 한다.
- **인물**: 국가 지도자와 장군이 있다. 장군은 기술 수준(1~5)과 특성을 가진다. 내각·고문 직책은 M4다.

### 4.3 경제 (ECO)

원작의 공장 종류별 배정 방식을 쓰지 않는다. 대신 **산업 역량 배분**과 **생산 라인 효율**을 결합한다.

1. **산업 역량(IC)**: 각 주의 공업 시설 수준을 합산하고 보정치를 곱해 국가 IC를 구한다.
2. **배분**: 국가 IC를 네 부문에 비율로 나눈다.

   | 부문 | 역할 | 규칙 |
   |---|---|---|
   | 소비재 | 국내 수요 | 하한이 있다. 하한은 경제 법령과 안정도로 정해진다. |
   | 건설 | 건설 프로젝트 | 프로젝트당 투입 상한이 있다. |
   | 군수 생산 | 생산 라인 | — |
   | 수출 | 세계 시장 대금 | 자원 구매에 쓴다. |

   플레이어가 비율을 조정한다. AI 기본 비율은 데이터 값이다.
3. **생산 라인**: 장비 모델 하나를 지정하고 군수 IC를 할당한다.
   - 효율은 시작값에서 시작해 매일 상한(기술로 상승)까지 오른다.
   - 다른 모델로 바꾸면 효율 일부를 잃는다. 같은 계열의 신형이면 덜 잃는다.
   - 일일 산출은 `할당 IC × 효율 × 자원 충족률 ÷ 장비 단가`다.
4. **전략 자원**: 종류는 데이터로 정한다. 기본 게임은 석유·철강·알루미늄·고무·희소금속 5종이다.
   - 주별로 산출된다.
   - 장비마다 단가당 자원 소요가 있다.
   - 부족하면 해당 라인의 자원 충족률이 떨어진다.
5. **세계 시장(M3)**: 부족한 자원은 수출 부문 IC를 대가로 산다. 국가 간 개별 무역은 M4다(REQ-ECO-08).
6. **건설**: 건물 종류, 주별 슬롯 상한, 단계별 비용은 데이터로 정한다.
   - 대상은 공업 시설, 인프라, 보급 거점, 철도, 항구, 진지 등이다.
   - 대기열 순서대로 건설 IC를 받는다.
   - 인프라 수준이 건설 속도를 보정한다.
7. **인력**: 주 인구 × 징병 법령 비율로 가용 인력이 생긴다. 사단 훈련과 보충에 쓴다.

**WP-14/W2 한정 CEO 잠정 — 2026-10-08.** REQUEST-0010 A-CEO-r1 (기술 범위: [공개 인계 기술 메모](technical-notes.md))의 수정판을 기술 잠정으로 채택했다. 사용자 추가 확정 답은 없으며 D·OPEN 상태는 바꾸지 않는다. 새 경제 정의가 있는 실행에만 적용한다. 원 M0/M1과 None/v1~v4 저장·해시·fixture는 유지하고 W1 전체 통합 뒤 실제 schema와 독립 검증으로 인수한다.

- 국가 IC·자원 산출·징병 대상 인구는 소유 주에서 집계한다. W2는 통제 비율에 따른 점령 수익을 추정하지 않는다. 소비재 하한은 경제 법령의 데이터 `clamp(base + instability_slope × (1 - stability), 0, 1)`이다. 네 비율은 각각0~1/정확합1이며 하한 미달은 transaction 전체 거부다. 고정소수점 배분 잔여는 소비재에 귀속한다. 자원은 일일 흐름이며 비축/생산 부족 효과/시장 거래는 실제 후속 consumer가 인수한다.
- 건설은 소유 주의 현재 수준+1 한 단계만 예약하며 같은 대상 건물 중복 예약과 슬롯/단계 초과를 거부한다. 원 IC 잔여를 같은 날 뒤 프로젝트에 넘기고 완료에 필요한 원 IC는 올림한다. 최소 단위 초과 유효 진행도는 폐기·원장 기록하며 일일 미사용 IC는 이월하지 않는다. cap0/인프라 보정0이면 배정·소비0으로 skip한다. 취소는 예약 해제·진행 폐기이며 환불하지 않는다. 완료 건물의 산출은 다음 일일 계산부터 반영한다.
- 소유권 상실 프로젝트는 queue·진행·목표·예약을 보존하고 휴면 사유와 함께 skip한다. 그 예약은 새 소유자의 활성 슬롯을 점유하지 않는다. 회복 시 목표/현재 수준/슬롯/정의를 다시 검사하며 충돌은 자동 완료·보상·삭제·단계 상승 대신 휴면으로 남긴다. 신규 점령/소유권 변경 게임 행동은 이 채택 범위가 아니다.
- 인력 capacity는 소유 주 인구 합×징병 비율의 정수 내림이다. 가용량은 `max(0, capacity - committed - reserved)`로 매일 같은 총량을 누적 지급하지 않는다. 초기 committed/reserved는 데이터가 명시한다. 감소 시 기존 소비·예약을 삭제하지 않는다. 예약/확정/소비/반환은 권위 내부 API이며 실제 훈련·보충 consumer 없이 플레이어에게 인력 생성/임의 반환 명령을 노출하지 않는다.
- 기존 02 §6.2 일일 순서(경제→생산→건설→인력→연구→정치)를 유지하고 PC는 Politics에서 한 번 지급한다. 경계 틱 법령 명령은 지급 전 PC로 검사한다. 동일 법령/부족 PC/조건 실패/변경 후 하한 위반은 전체 거부하며 단계를 직접 바꿀 때 중간 비용을 숨겨 더하지 않는다. PC 상한과 안정도·동원도 범위, checked overflow·multi-effect 전체 rollback·wholephase state/queue/clock/RNG 불변을 검사한다. 미지원 조건/효과는 값0도 capability 오류다.

상세 수치 단위·예약 충돌·날짜 경계 독립 예제와 호환 계약은 위 수정판이 기준이다. 이 producer 단계의 통합으로 REQ-NAT-03/REQ-ECO-04/REQ-ECO-07의 후속 생산·항복·군사/훈련 consumer 또는 전체 M2를 완료했다고 기록하지 않는다.

### 4.4 연구 (TEC)

- 기술은 데이터 노드다. 범주, 기준 연도, 비용, 선행 기술, 효과(장비·건물 해금, 보정치)를 가진다.
- 국가는 연구 슬롯 수만큼 동시에 연구한다. 기본 슬롯 수는 데이터 값이고, 의제·이벤트로 늘어난다.
- 기준 연도보다 먼저 연구하면 비용이 늘어난다. 증가율은 데이터 값이다.
- 장비 모델은 세대로 이어진다. 구형 장비도 계속 사용할 수 있다. 신형 생산 라인 전환 손실은 §4.3을 따른다.

### 4.5 의제·이벤트·결의 (AGD)

- **국가 의제**: 노드 그래프다.
  - 노드 속성: 소요 일수, 선행 조건(전부/하나 이상), 배타 노드, 가용 조건, 효과, AI 가중치.
  - 한 번에 하나만 진행한다.
  - 고유 트리가 없는 국가는 범용 트리를 쓴다.
- **이벤트**: 발동 방식은 두 가지다. 조건과 평균 발생 일수로 매일 판정하거나, 다른 효과가 직접 발동한다. 선택지마다 효과와 AI 가중치가 있다.
- **결의**: PC 비용, 조건, 효과, 지속 기간, 재사용 대기를 가진다.
- **트리거·효과 문법**: 의제·이벤트·결의·시나리오 종료 조건이 공통으로 쓴다. 선언형 데이터 문법이다(02 §5.6). 스크립트 언어는 OPEN-06이다.

### 4.6 외교 (DIP)

- **국제 긴장도**: 0~100%다. 명분 생성, 병합, 선전포고 같은 행동으로 오른다. 다른 국가가 할 수 있는 행동의 조건이 된다(예: 보장은 긴장도 X% 이상).
- **진영**: 창설·가입·초대·탈퇴가 가능하고 진영 리더가 있다. 진영 리더가 참전하면 진영 전체가 참전한다(예외 규칙은 데이터).
- **명분**: PC와 기간을 들여 대상국에 대한 명분을 만든다. 긴장도 조건이 붙는다. 명분이 있어야 선전포고할 수 있다(M3, 규칙 상수는 데이터). M2 Testland에서는 명분 없이 선전포고할 수 있다.
- **보장·통행권·불가침 조약**: M3.
- **전쟁 상태**: 전쟁마다 공격 측·방어 측, 참전국, 시작일을 가진다.
- **항복 진행도**: 자국 핵심 영토의 승점 중 적이 통제하는 비율에 안정도·법령 보정을 곱한 값이다. 임계값(데이터 값, 예시 80%)을 넘으면 항복한다.
- **강화(단순, M3)**: 항복한 국가의 영토는 그 땅을 통제하는 국가에 넘어간다. 진영 리더는 괴뢰국 수립이나 반환을 선택할 수 있다(AI는 데이터 가중치로 판단). M2에서는 통제국 이전만 한다. 상세한 평화 회의는 OPEN-02다.

### 4.7 군사 (MIL)

- **장비**: 종류와 능력치를 데이터로 정한다. 국가별 비축량이 있고, 생산 라인이 비축을 채운다.
- **편제**: 전투 대대 최대 12개와 지원 중대 최대 4개로 구성한다. 원작식 격자 배치는 쓰지 않는다. 사단 능력치는 구성 대대에서 자동 계산한다.
  - 조직력, 전력, 대인 화력, 대물 화력, 방어, 돌파, 장갑, 관통, 속도, 전면 폭, 보급 소모, 인력, 장비 요구.
- **초기 편제 계산 사용자 승인(2026-10-08):** 장비 family마다 실제 생산 registry의 모델 하나를 명시하고, 정상 구성 능력치를 필드별 합계 또는 인력 가중 평균으로 계산하며 속도는 구성의 최저 속도를 쓴다. 초기 로컬 단위의 필드 대응은 전력·대인/대물 화력·방어·돌파·전면 폭·보급 소모의 합계, 조직력·장갑·관통의 인력 가중 평균, 인력·장비 요구의 정수 합계다. 보급 소모는 정상 편제의 선언된 요구 메타데이터이며 실제 감편 사단의 일일 수요가 아니다. 고정소수점 가중 평균은 넓은 정수 누산 후 최종 몫에서 한 번 내림한다.
  - 현재 생산 모델에는 전투 능력치가 없으므로 구성별로 명시한 정상 능력치와 모델 binding을 대조한다. 장비 개수당 전투 기여, 대대 능력치와 장비 능력치의 중복 합산, 모델 변경 시 능력치 자동 파생을 이번 승인으로 확정하지 않는다. 같은 구성을 반복한 입력은 횟수를 보존하고 인력이0인 지원 구성은 평균 가중치0이다. 빈 구성·전체 인력0의 정의는 읽을 수 있으나 최저 속도나 평균이 정의되지 않으면 계산 불가를 보고한다. 이것은 편제 편집기의 배치 가능 조건을 새로 확정한 것이 아니다.
  - 훈련 예약·진행·취소·반환·보충과 실제 사단/OOB·감편 수요·손실·일일 효과·저장·wire·UI는 후속 계약이다. D·OPEN 상태를 추가 변경하지 않는다.
- **훈련·보충 사용자 승인(2026-10-09):** 아래 네 정책으로 실제 사단·군 소속, 자원 소유, 저장·조회 계약을 구현한다. 정상 편제 계산의 후속 단위이며 전체 WP-16/M2 완료 판정은 독립 검증과 같은 main CI 뒤에도 범위별로 구분한다.
  1. 훈련 요청은 자원을 빼지 않는 Pending 큐에 들어간다. 매일 처리에서 정상 편제의 인력을 전부 확보하면 시작하며, 장비가 부족해도 훈련은 계속된다. 시작일 진행은0이고 다음 날부터 데이터의 양의 정수 훈련 일수를 센다. 인력은 일부만 예약하지 않고, ID 순으로 대기 요청을 검사하면서 뒤의 작은 요청도 검사한다. Capacity 감소로 이미 시작한 훈련의 예약을 없애지 않는다.
  2. 현역 사단의 인력·장비 보충을 훈련보다 먼저 처리한다. 군 우선순위는 숫자가 낮을수록 높고0이 최우선이다. 높은 군 우선순위부터 배분하고 같은 우선순위의 모든 사단 부족량에 비례한다. 정수 나머지는 최대 나머지 순, 동점은 사단 ID 순으로 배분한다. 훈련 중·Ready 장비도 부족량 비례, 동점 요청 ID 순이다. 선택한 모델은 자동 교체하지 않는다. 첫 버전에는 별도 보충 속도 제한·수송 지연·추가 비용이 없다.
  3. 훈련을 마치면 Ready로 기다린다. 플레이어가 자기 군과 현재 통제하는 육지 위치를 선택해 배치하고 그때 군 사단 상한을 검사한다. 장비 부족 배치는 명시적으로 요청하며 장비0도 허용한다. 최소 장비 비율과 조기 배치는 없다. 배치 때 이미 예약한 인력을 committed로, 보유 장비를 사단 소유로 한 번만 옮긴다. 새로운 전투·감편 효과·보급 수요 공식은 이 승인으로 만들지 않는다.
  4. 취소는 실제 예약 인력과 실제 보유 장비 전부를 원래 소유국에 반환하고 진행만 버린다. Pending의 반환은0이며 배치한 사단은 훈련 취소로 되돌리지 않는다. 반환 공간을 사전에 보장하도록 모델별 창고량과 반환 가능한 훈련 장비 합계를 기존 비축 상한 안에 유지한다. 생산도 이 합계를 검사하고 기존 전체 단계 실패·원자성 계약을 따른다. 인력 취소는 reserved를 해제하며 capacity를 더하지 않는다.
  - 기존 명령→시계 진행→daily 순서를 유지한다. 훈련/보충은 경제·생산·건설 뒤에 실행한다. 같은 step의 취소가 daily 완료보다 먼저 적용되고, 아직 Ready가 아닌 배치 명령은 그 step에서 완료 예정이어도 거부한다. 예정 의미 오류의 명령 소비와 전체 단계 오류의 상태·큐·시계 rollback을 구분한다.
  - 실제 군사 입력은 명시적으로 선택한 팩 정의가 권위다. 기존 익명 committed/reserved를 임의 사단·훈련으로 재해석하지 않고 배경량과 실제 소유 합계를 검증한다. 군사 입력이 없는 기존 팩·v1~v6 저장·해시·wire는 보존한다. 기존 외부 정상 편제 sidecar의 진단 identity를 저장 권위로 사용하지 않는다.
  - **후속 사용자 승인(2026-10-09):** 전 세계 평생 누적 훈련4096건 제한을 없앤다. 국가별 Pending·Training·Ready 합계에 기존 크기의 기술 상한4096건만 적용한다. Ready는 배치 대기이므로 계속 계산하고 Cancelled·Deployed는 슬롯을 돌려준다. 종료 기록·다음 단조 증가 ID·저장/재개·기존 중복 요청 거절을 보존한다. 종료 이력 보존 정책을 암묵적으로 바꾸거나 작은 게임플레이 한도를 새로 만들지 않는다.
- **사단 생성**: 훈련 기간이 있다. 인력과 장비를 할당한다. 장비가 부족하면 감편 상태로 배치할 수 있다.
- **보충**: 비축에서 장비, 인력 풀에서 인력을 보충한다. 우선순위는 군 단위로 설정한다.
- **군**: 장군 1명이 지휘하고 사단 상한(데이터, 예시 24)이 있다. 장군 기술 수준이 공격·방어·보급 효율을 보정한다. 집단군 계층은 M4다.

### 4.8 전투 (CMB)

전투는 **프로빈스 단위**다. 공격 측은 인접한 여러 프로빈스에서 동시에 참여할 수 있다. 피해는 매 틱 계산한다.

1. **전면 폭**: 지형별 기본 폭에 공격 방향 수에 따른 추가 폭을 더한다. 전면 폭 합계를 넘는 사단은 예비대로 대기하고, 조직력이 낮아진 사단과 교대한다.
2. **화력**: 각 사단의 화력은 `대인 화력 × (1 − 대상 장갑화율) + 대물 화력 × 대상 장갑화율`이다.
3. **상쇄**: 방어 측 사단은 `방어`로, 공격 측 사단은 `돌파`로 받는 화력을 상쇄한다. 상쇄된 화력과 상쇄되지 않은 화력은 서로 다른 피해 계수를 받는다(`defines`).
4. **피해**: 기대값으로 계산하고, 시드 난수로 ±분산(데이터 값, 예시 15%)을 준다. 피해는 조직력과 전력에 계수별로 나눈다.
5. **장갑 우위**: 상대 관통보다 장갑이 높은 쪽은 받는 피해가 줄고, 상대에게 주는 조직력 피해가 늘어난다(계수는 `defines`).
6. **보정**: 지형, 하천 도하, 진지 수준, 보급 비율, 장군, 포위, 공중 우세(M4)를 수치 원장 항목으로 곱하거나 더한다.
7. **종료**
   - 방어 측 전원의 조직력이 0이거나 전원이 퇴각하면, 방어 측은 인접 아군 통제 프로빈스로 퇴각하고 공격 측이 진입한다.
   - 퇴로가 없으면 섬멸한다.
   - 공격 측 조직력이 모두 소진되면 공격이 중지된다.
8. 모든 전투 계산은 수치 원장에 기록한다. UI에서 전투 상세 창으로 볼 수 있다(REQ-CMB-06).

### 4.9 보급 (SUP)

- **보급원**: 수도, 보급 거점 건물, 항구다. 보급 거점과 항구는 철도로 수도와 연결되어야 활성화된다.
- **용량**: 각 보급원은 처리량을 가진다. 처리량은 철도 수준으로 제한된다. 보급원이 프로빈스에 주는 보급 용량은 이동 비용 기반 그래프 거리에 따라 줄어든다. 감쇠 곡선은 `defines`다.
- **보급 비율**: 프로빈스 보급 용량 ÷ 그 프로빈스 사단들의 보급 소모, 상한 1이다.
  - 1 미만이면 조직력 회복, 공격, 이동에 페널티가 붙는다.
  - 일정 기간 이상 0.3 미만(데이터 값)이면 전력이 손실된다.
- **포위**: 보급원과 연결이 끊기면 보급 비율이 0이 된다.
- 사용자 2026-10-06 답변으로 보급 차량 소모를 포함하고 철도 궤간 변환은 제외한다(OPEN-03).
  - **CEO 잠정 채택(2026-10-07, M4 적용 전 계약 대조 필요):** 차량 v2 구체 설계 (기술 범위: [공개 인계 기술 메모](technical-notes.md))의 명시 예약/자동 보충 없음, 운용량 기반 두 단계 floor 공급 계산, 소수 손실 이월, 기존 보급→경제→생산 순서, 예약 소유국 반환과 L 수명 정책을 따른다. Q=2^32, 필요량 N=ceil(C_raw×k/Q), 운용량 O=min(A,N), F_raw=floor(O×Q/N), 공급 E_raw=floor(C_raw×F_raw/Q), 손실 D=floor((L+O×r_raw)/Q)와 소수 나머지 이월이다. N=0이면 운용/손실0·L 보존이다. 창고 W와 예약 A를 분리하고 유효 총계 상한 안에서 반환 가능성을 보장한다.
  - 구현 전에 WP-15의 실제 장비/재고형·재고상한, 보급 C 단위, phase/명령/서버 오류 계약을 대조한다. 장비/Hub ID·형/상한 차이는 재검토한다. 합성 k/r 예제는 실제 콘텐츠 기본값을 정한 것이 아니다. 예정 의미오류의 W/A/L 보존과 성공 step의 큐소비/clock 진행을 구분하고, phase 오류는 전체 step 복제본을 commit하지 않는다.
  - 이 잠정 채택만으로 WP-15 생산 규칙·기존 저장 거부·호환 파괴·migration을 실행하지 않는다. 실제 모델/호환안을 먼저 검토한다. D·OPEN 확정 상태는 추가 변경하지 않는다.

### 4.10 공군·해군 (AIR·NAV)

- **M3**: 해상 수송만 있다. 사단을 항구에서 항구로 옮기며, 거리에 비례해 시간이 걸린다. 해상 전투는 없다.
- **M4**: 공역별 공중 우세를 배치된 전투기 전력의 비율로 계산하고, 근접 지원이 전투 보정을 준다. 해역 통제, 호송 차단, 상륙 작전이 추가된다.
- **M5**: 사용자 2026-10-06 답변으로 전략 폭격·세부 공군 임무(OPEN-04)와 함대 전투(OPEN-05)를 포함한다. 세부 임무·전투 공식·수치는 후속 결정이 필요하다. 함선 설계는 이후 구현 로드맵에 보존하며 도입 시점·세부 범위는 미정이다. OPEN-01의 차체·모듈 설계를 함선 설계까지 확대하지 않는다.

### 4.11 AI

- 비플레이어 국가는 모두 AI가 운영한다.
- **계층**: 전략(위협 평가·목표), 경제(배분·건설·생산), 연구·의제, 외교, 군사(전선 배분·공세 판단·공세 계획 생성·실행).
- 플레이어가 지정한 전선·공세 계획도 같은 군사 실행 계층이 처리한다. 플레이어와 AI가 같은 규칙으로 싸운다.
- AI는 결정론적이다. 국가별 예산은 시간이 아니라 **작업 단위**로 제한한다(DR-08).
- **역사 경로 옵션**: 켜면 AI가 데이터에 표시된 역사적 선택에 높은 가중치를 준다.
- **평가**: 헤드리스로 AI 대전을 여러 번 실행해 지표를 낸다(REQ-AI-07). 목표 지표값은 사용자가 정한다. 에이전트는 측정만 한다.

## 5. 화면 흐름

브라우저로 서버 주소에 접속하면 메인 메뉴가 열린다. 로컬 싱글플레이라면 서버를 실행했을 때 브라우저가 자동으로 열린다.

```
메인 메뉴 ─┬→ 새 게임 → 시나리오 선택 → 국가 선택 → 게임 화면 ─┬→ 결과 화면 → 메인 메뉴
          ├→ 불러오기 ─────────────────────────────────┘    │
          ├→ 모드 관리 (활성·순서·검증 결과)                    ├→ 일시정지 메뉴(저장·불러오기·설정·종료)
          ├→ 설정 (언어·UI 배율·단축키·자동 저장·그래픽)          └→ 각종 패널
          └→ (M6) 멀티플레이 로비
```

**게임 화면 구성**

| 영역 | 내용 |
|---|---|
| 상단 바 | 국기·국가명, 날짜, 속도, PC, 안정도, 동원도, IC(배분 요약), 인력, 자원 경고, 알림 |
| 지도 | 지도 모드 전환(정치·지형·주·보급·인프라·자원·외교), 선택·호버, 부대 표시, 전선·공세 화살표 |
| 좌측 패널 탭 | 정치·법령, 연구, 산업(배분·생산), 건설, 외교, 편제, 의제, 군 |
| 하단 | 선택한 군·사단 정보와 명령 버튼 |
| 팝업 | 이벤트(선택지), 결의 창, 전투 상세(수치 원장) |
| 툴팁 | 모든 파생 수치에 **수치 원장**(기여 항목·연산·출처)을 표시 |

## 7. 법적 원칙 (클린룸)

조사 근거는 02 §16에 있다. 핵심은 다음과 같다.

1. 미국 저작권청 안내에 따르면 게임의 아이디어나 규칙 자체는 저작권 보호 대상이 아니다. 하지만 한국 대법원 2019.6.27. 선고 2017다212095 판결은 규칙들의 **선택·배열·조합**에 창작적 개성이 있으면 보호될 수 있다고 봤다. 그래서 원작 시스템 전체를 같은 조합으로 충실히 재현하는 것은 피한다. 차별화 내역은 §11에 기록한다(REQ-LEG-05).
2. **사용 금지**
   - 원작의 파일, 스크립트, 현지화 문자열, 이미지, 아이콘, 음원
   - 원작 프로빈스 지도와 그 트레이싱
   - 원작 수치표 복제
   - 실행 파일 디컴파일
3. HOI4 위키 문장은 CC BY-SA 3.0이다. 문장을 복사하지 않는다. 사실이나 방법을 참고했다면 자체 문장으로 다시 쓴다.
4. 상표: 공개 명칭은 D-12에서 정한다. "Paradox Interactive와 무관"이라는 고지를 단다(REQ-LEG-04).
5. 국기와 상징: 독일 등에서 금지된 위헌 단체 상징은 쓰지 않는다. 역사 국기는 대체 디자인을 쓴다(REQ-LEG-06).
6. 지도 원천 데이터: Natural Earth(퍼블릭 도메인)와 OpenHistoricalMap의 CC0로 검토된 요소만 쓴다. OHM의 license 태그 예외 및 OSM 수입 해안/수역/하천의 별도 라이선스를 원시 자료 전체의 CC0로 취급하지 않는다. 현재 허용 원천·라이선스 범위를 확대하지 않는다. 비영리 조항이 있는 CShapes는 쓰지 않는다. historical-basemaps는 현재 원천 목록에 없으므로 D-10 확정만으로 배포에 추가하지 않는다.
7. 사용자 2026-10-06 지시로 지리 원천은 제작·취득 단계에서 버전 고정 파일로 보존한다(URL·취득일·버전/snapshot·라이선스·SHA256). 오프라인 생성기가 그 파일로 프로빈스·정의·주·인접·지형 팩을 만든다. 게임 실행과 브라우저 지도는 동봉 팩·자체 로컬 HTTP만 사용하고 외부 지리 API·타일 서버·CDN을 요청하지 않는다. 원천 누락을 실시간 다운로드로 숨기지 않는다. 입력·산출 해시로 재생성을 검사한다(REQ-MAP-10).
8. 사용자 2026-10-06 고도 지시로 독립 DEM 원천을 필요한 범위에서 추가할 수 있다. 고도·능선·하천을 로컬 snapshot에 보존해 프로빈스 생성/검수에 반영한다(REQ-MAP-11). 사용자 확인 답은 "공개 화면의 분할 원칙만 참고"다. 공개 플레이 화면의 산맥·강·도시 주변 분할 원칙·밀도 비교만 허용하며 원작 경계 복사·트레이싱·파일 추출/사용·수치표는 금지한다. 새 이동/전투 계수는 이 지시만으로 만들지 않는다.

## 11. 원작 대비 설계 차별화 기록

갱신 절차: 구현 세션은 해당 WP 작업 로그에 원작 구조·OpenHOI 구조·차별화 이유의 행 초안을 남긴다. 독립 검증 세션은 실제 구현과 초안이 맞는지 확인한다. 오케스트레이터는 PASS 후 통합할 때 이 표에 반영하고 관련 WP·검증 리포트를 기록한다. 원작의 파일·수치·문장을 조사 자료로 가져오지 않는다. 미구현 시스템은 구현된 것으로 기록하지 않으며, 결정 상태 변경은 사용자 답변이 있을 때만 한다.
