## 증거
- E1: `docs/worklog/evidence/WP-04/`의 실제 명령·exit_code·출력. 실패 로그도 보존한다. diff-staged-initial.txt와 diff-staged-second.txt의 exit 2는 cargo-deny 및 그 공백 검사 진단을 저장한 출력의 공백 패딩이었다. 진단 내용은 그대로 패딩만 정리한 발췌로 보존하고, 최종 기준 커밋 대비 전체 변경 공백 검사를 통과했다.
- E2: `crates/oh_sim/tests/scheduler.rs`, `crates/oh_cli/tests/run.rs`, `crates/oh_sim/tests/test_sim_determinism.py`와 red/final 로그.
- 로컬 실제 Windows 출력: windows-run-1.txt, windows-run-2.txt, windows-sim-hash.txt. 최종 수집기의 stdout 원문이며 hash는 ff921fd8148e699d.
- 실제 세 OS CI 예정: `.github/workflows/sim-determinism.yml`. OS별 sim-hash-<runner> 아티팩트에 두 stdout와 hash 파일을 보존한다. 비교 job이 세 OS 존재·정확한 hex·반복 및 OS 간 일치를 요구한다. 구현 세션은 실행/성공으로 기록하지 않는다.
- E3/E4/E5: UI·벤치·재현 번들은 이번 범위가 아니므로 없음. 클라이언트/프로토콜/서버는 편집하지 않았다.
- E6: 독립 검증 세션이 아직 실행하지 않았다. PASS/게이트/통합은 이 세션이 판정하지 않는다.

## 범위 밖 발견
- 기존 WP-03 테스트의 Testland empty 정의 가정과 time 정의가 충돌했으나, 테스트 수정 없이 최소 M0 예제 팩 분리로 해결했다. 오케스트레이터 추가 지시로 분리를 허용받고 중복 manifest ID를 없앴다.
- `--scenario testland`의 실제 입력은 `data/packs/examples/m0/testland/{manifest.toml,defines.toml,scenarios/testland/scenario.toml}`다. manifest ID는 **m0_testland**, scenario ID는 **testland**다. depends/conflicts/load_after는 모두 빈 목록이며 다른 팩을 읽지 않는다. 원래 `data/packs/testland`는 원본이다.
- WP-05 재사용 경계: `oh_cli::M0_PACK_ROOT`, `oh_cli::load_scenario(root, scenario_id)` → LoadedScenario(팩 메타데이터·날짜·TimeConfig), `LoadedScenario::simulation(seed)` → 진행 전 Simulation. 서버는 `enqueue(current_tick, nation, arrival_sequence, Command)`와 `step()`을 pause 중에도 호출하며 `snapshot`, `ms_per_tick`, `state_hash`를 조회한다. 서버 권한/실시간 pacing·프로토콜 타입은 WP-05 소유이며 수정하지 않았다.
- 완전한 시나리오 콘텐츠/팩 병합/참조/엔진 호환 검사와 종료 조건은 WP-23·WP-24·WP-13 등 후속 범위다.

## 못 한 부분과 이유
- REQ-GEN-06의 validate/ai-bench/bench/repro 등은 이번 명시적 M0 run 범위 밖이다. 없는 명령을 실행하거나 통과했다고 쓰지 않았다.
- 서버·클라이언트 연결, 사용자 화면·현지화, Playwright, TS 생성은 WP-05 범위다. 이번 변경에는 제품 화면 문자열이 없다.
- 이동·전투·경제·정치·AI·월간 통계의 실제 게임 처리는 후속 시스템 WP다. M0에서는 빈 슬롯 순서만 있다. AI mod 7 분산/작업 예산은 AI가 없으므로 동작으로 구현했다고 주장하지 않는다.
- 저장 후 재개(DR-10), 저장 파일/번들은 후속 WP 범위다. 포맷 호환을 만들거나 깨뜨리지 않았다.
- 실제 Linux/macOS 해시, branch/main CI, 독립 PASS와 통합 게이트는 오케스트레이터가 수집할 증거다. 이 세션은 로컬 Windows 증거와 workflow만 제공하며 기본 브랜치·원격을 편집/병합/푸시하지 않는다.
