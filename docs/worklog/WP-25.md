## 증거
- E1: 초기 RED와 중간 실패/재시도 원출력. 기본 M0 Active localization 실패를 우회하지 않고 새 세션 기본 national m1을 사용했다. 내부 태그 unit variant가 unknown field를 무시하던 오류를 빈 struct variant로 고쳤다. 원 기존 target 보존 테스트가 이 문제를 잡았다.
- E2: 실제 stdin Host가 EOF 전에 event를 flush하고, EOF 뒤 ZIP에 시작 저장과 새 입력순서·실제 결과·종료 report를 담는다. fresh native replay가 종료 DTO/canonical/hash를 대조한다. snapshot pending은 한 번만 복원한다. 의미오류 소비와 wholephase ClockOverflow rollback을 구분하고 pause rescue의 동일 큐를 확인했다.
- E2 경계: paused 같은 tick의 여러 pump, 기존 예약 이동/Stop의 v2, v3 해협 진행/도착, v4 flags·effect/end checkpoint·ended step/enqueue 거부·미래5명령 보존·empty/initial/paused_condition을 실제 codec/CLI/별도 producer process로 대조했다. fixtures는 명시적 synthetic context이며 실제 CLI record 기능의 유일 입력원이 아니다.
- E2 ZIP: absolute/drive/UNC/../backslash/NUL/case/정규화 alias/중복/unknown/missing, ZIP member symlink/reparse, 실제 Windows junction input/output, CRC/잘림/중앙·local 길이/offset/flags/method/extra/선언 상한/압축 bomb, schema/seed/context/참조·log·fullDTO/canonical/한 비트 hash 변조를 거부했다. ZIP은 추출하지 않는다. compressed ZIP은 명확히 거부하고 start.ohsave의 bounded zstd는 보존한다.
- E2 I/O: 기존 output/inputsave/pack SHA·bytes 보존, 실제 tempfile prefix17bytes write 후 주입 I/O 실패의 native Rust 검사, Windows exclusive handle 때문에 실제 sync된 tempfile persist가 실패하는 native CLI 검사와 cleanup을 확인했다. Windows directory sync durability는 이 결과로 확정하지 않는다.
- E3: 사전 고정 prior 실제 라이브러리를 별도 read-only archive source로 빌드했다. build/download/pack load/warmup은 elapsed 밖이다. 각 source의 lock registry version/checksum을 감사하고 compiler/profile/features/pack 파일 bytes/SHA·seed/work량·native elapsed·실제 종료 tick/DTO/canonical/hash와 원 환경을 보존한다. 측정missing/0/비유한/실행실패는 오류다.
- 최종 인수 도구 `python -X utf8 tools/wp25_evidence.py`: committed source 변경파일 raw snapshot/길이/SHA, 전체 tracked 목록/각SHA·Git HEAD/status/index/diff, 원 실행증거를 SHA256SUMS.json과 evidence.zip에 보존하고 모든 member의 raw bytes/SHA/CRC를 재대조한다. ZIP-IDENTITY.json에 원ZIP파일수와 각SHA·전체ZIP SHA를 기록한다. 기존 build target/cache/baseline checkout 자체는 제외하되 archive 원 stdout과 build/metadata/env/lock/driver 원문을 포함한다.

## ADR

## 범위 밖 발견
- 초기 workspace clippy는 client/dist 부재로 oh_server build script가 native101을 냈다. 지정 worktree의 기존 npm ci/build 선행절차로 해결했고 기존 서버/빌드/CI를 변경하지 않았다.

## 못 한 부분과 이유
- Linux same-runner CI 및 exact 독립 P-05는 이 세션에서 실행/판정하지 않았다. 새 `performance.yml`의 필수 bench job과 artifacts를 부모가 검토한 exact branch push로 실행해야 한다. 구현 세션은 push/mainmerge/다른 세션 생성을 하지 않았다. 기존 6 CI·25 jobs와 실제 Save/Trigger 3OS 산출물은 변경하지 않았으며 그 전체 CI를 이 로컬 실행으로 재판정하지 않았다.
- 브라우저/WebSocket 게임 세션 recording은 추가하지 않았다. 02 §7.3 CLI headless game Host의 실제 stdin recording을 제공한다. M3/M5 성능목표·세계지도/3D/HUD 완료를 주장하지 않는다.
- 초기 확장 native harness 세 번은 개별 임시 fixture를 실행 끝에 정리하고 번호 파일을 재사용했다. 당시 래퍼 전체 stdout/stderr/native exit와 실패/재시도는 보존되지만 그 초기 개별 ZIP/스트림의 일부는 복원할 수 없다. 보존 요청 이후 harness를 고쳐 모든 새 native 실행마다 독립 디렉터리·argv/stdin/stdout/stderr·원 ZIP/입력/target snapshot을 보존했으며 최종 15개 검사 원증거를 인수한다. 삭제된 초기 fixture를 최종 원문으로 가장하지 않는다.

## 수정 기록 (P-06)
- 초기 metadata --locked가 신규 external workspace root 추가/미사용 package 정리 때문에101을 냈다. 원 source lock을 바꾸지 않고 source lock copy를 seeded offline metadata로 정리하고 registry version/checksum 유지 감사 후 --locked build로 수정했다.
- 설치된 Python3.11 patch에 tar extract filter API가 없어 TypeError가 발생했다. trusted exact git archive의 경로/regular type를 검증하고 개별 bytes로 복사했다. source는 read-only다.
- clock synthetic pack에 10자리 start year를 쓰면 Active validator가 거부한다. 실제 기존 save DTO의 유효한 calendar/tick/ledger 문맥을 갖춘 최대 clock fixture로 바꾸고 codec을 통과시켜 CLI에서 오류/보존을 검증했다.
- ZIP DOS 속성 unknown 거부를 엄격히 했고 unknown pump/step schema 거부를 수정했다. Windows 에러 문자열이 현지화되어 OS 영어 process 단어 단언을 API persist-error 단언으로 고쳤다. 파일 공유 금지 테스트의 evidence reader도 공유 금지에 실패하는 것을 별도 capture-error로 기록하고 handle release 뒤 원 bytes를 대조했다.
