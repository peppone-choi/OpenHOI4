## 계획
- 01·02의 WP-05 행, 시간 규칙, 프로토콜과 docs/protocol-m0-scope.md를 먼저 확인했다. 빈 Testland 시간 제어와 서버 호스트 경계만 구현했다.
- 구현 전에 Rust 계약/시작 오류 검사, TS 표시/MessagePack 검사, Playwright 실제 동작 요구 테스트를 작성했다. 최초 실패는 target/wp05에 보존했다.
- Rust 단일 타입 → ts-rs → TS 생성물, named MessagePack, 전용 동기 시뮬레이션 스레드 + bounded 명령 채널을 구현했다. 버전·명령 순번·지원 범위 거부와 현재 시간 Query, Snapshot/Delta/Notice를 실제 연결에서 확인했다.
- oh_cli의 기존 파일 입력 부분을 oh_data::m0에 최소 추출했다. 서버가 oh_cli에 의존하지 않는다. 기존 공개 CLI API와 시뮬레이션/골든을 유지했다. 이 추출은 이번 실행 지시의 명시적 허용 범위다.
- Vite production build를 서버 실행 파일에 임베드하고 로컬 주소/사용법/--help/--open/옵션 오류/포트 충돌/Ctrl+C를 구현했다. 데이터는 명시적 --pack-root 또는 저장소 상대 기본 경로로 로드한다.
- 최소 ko/en 현지화와 날짜·시각·틱·일시정지·5단계 속도 UI를 구현했다. 클라이언트는 게임 날짜/규칙/속도 계수를 계산하지 않는다.
- CI 서버는 매 push 세 OS, client는 Linux 세 엔진 E2E로 연결했다. 두 기존 결정론 workflow는 그대로 두었다. 다른 세션 생성, main 수정/병합/푸시, 설정 우회, README 수정은 하지 않았다.

## 증거
- E1: crates/oh_proto, crates/oh_server, client, 공유 oh_data::m0 및 기존 CLI wrapper. selftest/CLI orchestration 기록을 구현 성공 증거로 대체하지 않았다.
- E2: target/wp05/final-results.json 및 *-final.log, hash-first.log/hash-second.log. 구현자 자체 실행 결과이고 독립 검증 PASS 판정은 하지 않는다.
- E3/E4/E5: target/wp05/{chromium,firefox,webkit,chrome,edge}-{running,paused,ko}.png (15장), 각 *-browser.json. 실제 서버 http://127.0.0.1:4173, 빈 testland, 1280×720 viewport/fullPage, en-US browser locale, UI en/ko, headless DOM 셸, 일시정지/재개와 속도 5 상태. 최고 속도는 defines의 0ms/틱이므로 running 날짜는 촬영 순간에 따라 달라진다. GPU·지도·게임 프레임 성능 검사는 아니다.
- 로컬 제품/엔진 버전: Chromium 153.0.8010.12, Firefox 155.0, WebKit 26.6, Chrome 154.0.8037.98, Edge 154.0.4258.53. 제품은 기존 설치를 사용했다. Safari 제품과 추가 Chromium 파생 제품은 직접 실행하지 않았다.
- Chromium 일시정지·WebKit 한국어 스크린샷을 눈으로 확인했다. WebKit의 초기 native select 저대비를 발견하고 dark color-scheme으로 수정 후 재촬영했다.
- .github/workflows/ci.yml: server 세 OS build/test/lifecycle, Rust→TS wire 계약/TS 최신 생성 검사, Linux 실제 서버+세 엔진 E2E 및 artifact 업로드. fresh checkout 빌드 순서를 명시했다. 이 브랜치를 푸시하지 않았으므로 새 GitHub 실행 링크·3 OS 결과는 아직 없다.
- target 산출물은 git 제외 상태로 이 전용 worktree에 보존한다. 독립 검증자가 자신의 worktree에서 새 실행 증거를 만들어야 한다.

- oh_cli 내부 로드 경계의 추출은 이번 지시로 허용된 최소 확장이다. oh_data/src/m0.rs·lib.rs와 oh_cli/src/lib.rs만 수정했다. 서버→CLI 의존이나 sim I/O를 추가하지 않았다. ADR-0501과 이 로그로 root에 변경 범위를 보고한다.

## 못 한 부분과 이유
- 구현 세션 역할상 독립 검증 판정·기본 브랜치 병합·푸시/CI 결과 확인은 하지 않았다. 오케스트레이터의 독립 세션 및 통합 절차가 남아 있다.
- Linux/macOS 서버와 Safari 제품은 이 Windows 환경에서 직접 실행하지 않았다. 세 OS CI와 Linux 세 엔진 검사를 연결했으며 실행 전 성공으로 기록하지 않는다. Linux/macOS --open의 실제 기본 브라우저 통합도 미측정이다.
- oh validate, ai-bench, repro는 아직 후속 WP 명령이므로 실행했다고 기록하지 않았다. data/packs/testland(WP-03 빈 defines)을 M0 실행팩으로 바꾸지 않았다.
- REQ-NET-02의 M1 지도/그래픽 전체 요구는 아직 구현하지 않았다. 이 WP 증거는 임베드 정적 셸 및 ko/en 제공에 한정한다.
