## 범위 밖 발견

- check_docs.py는 ADR-숫자 문자열에서 DR 식별자를 부분 일치한다. 도구 변경 없이 검사용 문서의 참조 표현을 조정했다.
- GitHub Actions 사용량 조회 API는 현재 토큰 범위로 HTTP 404를 반환했다. 인증 권한을 확장하거나 지출 설정을 바꾸지 않았다. 무료 한도 내 실행이라는 제약을 계획에 유지한다.
- 앱 자동 worktree 생성의 clientThreadId 요청은 작업 폴더 생성만 관측했으며 정상 threadId/실행은 미확인이다. 진행에 쓰는 구현·검증은 명시적 Git worktree와 ready threadId 방식으로 구분한다.

## 못 한 부분과 이유

- WP-01의 main CI success를 확인했다. WP-06의 자체 독립 검증은 새 채팅에 맡기며 PASS 전까지 완료로 판정하지 않는다.
- CLI 하위 모델 인증 조합의 실제 정상 실행은 실패했다. 사용자 선택의 앱 호출 시험은 정상 종료했으나 CLI 성공으로 치환하지 않는다.

### 운영 문서 재검증 준비

첫 독립 검증이 88ef41f의 HANDOFF에서 상단의 main 워크플로 미통합과 하단 CI success의 모순을 직접 확인했다. HANDOFF를 현재 WP/채팅/CI 상태로 다시 썼다. CLI 시험 원본과 WP-00 done 1 이벤트를 추적 증거 경로에 보존했다. 동일 설정의 Git Bash selftest를 다시 실행하면서 PowerShell LASTEXITCODE를 직접 저장했고 2를 확인했다. 처음 도구 호출의 외부 PowerShell 종료 코드 1과 구분하며, 새 반복의 stdout/exit/stderr는 docs/worklog/evidence/WP-06/selftest-repeat.* 에 있다. 모델 HTTP 400은 그대로이며 설정은 바꾸지 않았다.

첫 검증 FAIL 리포트는 docs/verify/WP-06.attempt1.md에 보존했다. 유일한 FAIL은 HANDOFF의 상충하는 상태 기록이며 새 문서에서 현재 상태 표로 교체했다. 원본 CLI/앱 시험 자료도 커밋 가능한 증거 경로로 보존했다. 첫 검증의 종료 후 HEAD·index·추적 파일 status 무변경을 직접 확인했다. 수정된 커밋은 새 검증 채팅에서 검증한다.
