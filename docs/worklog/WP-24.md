- 기존 M0 example의 manifest name_key가 양언어 FTL에 없다. 부모는 M0 원팩 수정 불승인/legacy 실제 오류 기록을 지시했다. validate exit1 그대로이고 M0 기존 run/hash/save 경로는 유지한다.

- WP-13/14/15가 등록할 trigger/effect/end/경제/정치/장비와 WP-35 gameplay merging/patch/UI는 미구현 adapter다. 신규 미등록 TOML/FTL/CSV/PNG는 warning으로 노출하고 --deny-warnings에서 실패한다. 해당 producer는 typed loader/키/ref/진단 adapter를 연결해야 한다.
- client static scanner는 computed key 전체 runtime 집합을 증명하지 않는다. ko/en AST parity와 현재 resource-/building-/terrain generated DTO 입력은 검사하며 동적/서버 코드 사용키의 unused warning은 보수적 결과다. 실제 UI/runtime 증거는 해당 WP 후속이다.

## 못 한 부분과 이유

- 독립 검증/3OS/새 workflow 원격CI/기본main 통합은 구현 역할 범위 밖이다. 자기 branch commit까지만 수행한다.
- 미래 데이터 registry·팩 merge/patch·UI는 아직 producer/schema가 없고 담당 WP가 다르므로 구현하지 않았다. MOD-04 전체 미래 스키마 완료로 표시하지 않는다.
- M0 이름 현지화·base 콘텐츠는 파일 소유/현재 WP 범위 밖이며 요청받은 원팩 보존을 지켰다.
