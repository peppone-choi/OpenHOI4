## 서버 원장 결과·WP-09/WP-12 연결 API
- 타입 경로: `oh_sim::ledger::{Modifier, ModifierOp, LedgerOp, LedgerEntry, StatLedger, LedgerError}`. 이들은 시뮬레이션 내부 계산 타입이며 wire/TypeScript 타입을 중복 정의하지 않는다. 네트워크 표현은 WP-09의 oh_proto 소유다.
- 입력: `Modifier { source: String, target_stat: String, op: Add|Mul, value: Fx, expires: Option<u64> }`. 기본값/계수/출처는 대상 시스템의 데이터에서 공급한다. source/target_stat는 식별자이고 UI 현지화 키 연결은 표시 담당이 제공한다.
- 권위 계산: `StatLedger::evaluate(target_stat: &str, base: Fx, modifiers: &[Modifier], at_tick: u64) -> Result<StatLedger, LedgerError>`. 동일 연산만 필요하면 `formula::stat_value(base, target_stat, modifiers, at_tick) -> Result<Fx, LedgerError>`.
- 읽기: `target_stat() -> &str`, `tick() -> u64`, `value() -> Fx`, `entries() -> &[LedgerEntry]`. 기본행의 source=None/op=Base/value=base/accumulated=base, 다음 행의 source=Some(...)/op=Add|Mul/value=기여/accumulated=그 단계 실제 계산값이다. 마지막 accumulated는 value와 비트 일치한다. 항목 없는 경우도 기본행 하나가 있다.
- 적용/조회 경계: 소유 시스템은 성공 결과의 value를 적용하고 StatLedger 전체를 저장한다. 별도 적용값을 저장했다면 `verify_applied_value(applied: Fx) -> Result<(), LedgerError>`를 조회 직전에 호출한다. source/op를 포함한 Overflow 또는 DuplicateModifier, EmptyTargetStat/EmptySource, AppliedValueMismatch는 오류로 처리하고 부분 원장을 내보내지 않는다.
- 재계산: base/Modifier 변경 또는 expires 도달 시 현재 `Simulation::snapshot().tick()`으로 다시 evaluate해 결과 전체를 교체한다. expires==at_tick인 항목은 제외한다. 순수 조회는 Modifier를 제거하거나 상태를 변경하지 않는다. 물리적 보관/정리와 캐시 무효화는 WP-09/해당 시스템 소유다.
- 직렬화: Modifier는 Serialize/Deserialize로 Fx raw bits와 expires를 보존한다. StatLedger/entries/ops는 Serialize만 제공하며 결과를 입력으로 Deserialize하지 않는다. 재개 시 입력에서 원장을 재생성할 수 있다. 역순 입력은 동일 canonical ledger bytes로 확인했다. 원장 형식은 저장/네트워크 버전 계약으로 공표한 것이 아니다.
- oh_proto만 Fx를 표시용 수치로 변환한다. QueryResult에 target/tick/실제 최종값과 각 source/op/value/accumulated를 담고 WP-12가 그 서버 결과를 표시한다. 클라이언트는 Add/Mul이나 반올림을 다시 계산하지 않는다. 엔티티별 target 연결·권한·조회 메시지·현지화·패널은 WP-09/WP-12가 구현한다.
