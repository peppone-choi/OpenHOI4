## 질문 (한 문장)

이미 MapData에 정의된 육지 간 strait edge는 서버 내부의 명시 통과 허용과 양수 시간계수가 있을 때만 직접 이동 경로로 사용하는 A를 잠정 채택할 수 있는가?

01 §4.1은 해협 횡단 인접을 정의하지만 해협 시간계수와 통과 정책은 정하지 않았다. WP-31의 항구 간 해상 수송과 같다고 추정하지 않는다. 현재 WP-17 solver는 strait를 제외하므로 그 경계만 연결되면 NoPath다. 아래 후보는 기존 직접 이동·지도 인접 범위의 가역적 세부 사항이며 새로운 해군/해상 수송 시스템이나 원작 규칙이 아니다.

## 선택지

| 선택지 | 플레이 경험 | 구현 비용 | 위험 |
|---|---|---|---|

## 추천안과 이유

A. Defs의 실제 adjacency를 버리지 않으면서 모든 값과 권한을 서버 내부의 명시 context로 제한한다. 신규 시간계수는 콘텐츠 기본값을 만들지 않고 값이 없으면 MissingContext로 거부한다. 하천과 해협의 필드를 혼동하지 않는다. 클라이언트는 unit/목적지만 명령하며 allowed/속도/시간계수를 지정하지 않는다. M4 해역 통제·함대 봉쇄 효과는 구현하지 않는다.

독립 합성 예제는 육지 0→30의 strait edge 거리10km/속도2kmh, 다른 시간계수1, strait계수2로 10h다. 9틱 후 출발/elapsed9, 10틱 후 도착/빈 route elapsed0이다. 정상 대체 경로8h가 있으면 대체 경로를 선택한다. 계수 누락/0/음수/overflow, allowed 미포함, 비육지 끝점, 잘못된 참조는 생성 또는 명령 입력 경계에서 실패하고 상태/큐를 보존한다. save/hash/복원은 실제 applied 계수와 edge kind를 모두 대조한다. 이 수치는 검증용이며 실제 콘텐츠값 승인이 아니다.

## 기본안으로 먼저 진행할 경우 되돌림 비용

답 전 종속 동작은 구현하지 않는다. A 채택 뒤 변경은 아직 공개/병합하지 않은 WP-17의 crossing schema/solver 및 신규 fixture/문서 수정이다. 기존 v1은 유지하고 저장 거부·migration이나 기존 테스트 약화는 하지 않는다. 이후 저장된 crossing 상태의 지원 의미 변경은 별도 호환 검토가 필요하다.
