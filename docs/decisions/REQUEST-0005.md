# 결정 요청 REQUEST-0005 — OPEN-12 업적 세부 규칙

| 항목 | 값 |
|---|---|
| 요청일 | 2026-10-06 |
| 관련 식별자 | OPEN-12, REQ-GEN-08 |
| 막는 WP | WP-50 업적 규칙(M6) |
| 막지 않는 WP (계속 진행 중) | M1~M5, WP-49 멀티플레이 |

## 질문 (한 문장)

업적 목록·충족 조건·저장 방식과 모드/멀티플레이 적용 범위를 어떻게 정할 것인가?

## 선택지

| 선택지 | 플레이 경험 | 구현 비용 | 위험 |
|---|---|---|---|
| A: 데이터 기반 소수 업적과 로컬 기록의 후보안 | 작은 목록에서 목표 확인 | 기존 트리거·저장 경계 활용 검토 | 모드/버전/멀티 조건 세부 결정 필요 |
| B: 시나리오·모드별 넓은 업적 체계 후보안 | 많은 목표 선택 | 콘텐츠·UI·기록 규칙 증가 | 호환·중복 획득·검증 정책 결정 다수 |

## 추천안과 이유

A 후보안을 M6 전 구체화해 사용자에게 검토받는다. 공개 계정이나 아이언맨을 전제하지 않고 완료 조건·버전·재현과 저장 연결은 결정론을 유지해야 한다. 실제 업적 조건과 수치를 아직 만들지 않는다.

## 기본안으로 먼저 진행할 경우 되돌림 비용

문서·인터페이스 조사만 가능하다. 획득 조건·저장 규격을 선행 구현하지 않아 되돌림을 피한다. M1은 계속 진행한다.

## 사용자 답 (사용자 또는 사용자 답을 옮긴 메인 에이전트가 기록)

범위 확정: "업적만 포함". 아이언맨 제외. 이 요청의 세부 조건·기록 방식에는 답변 없음.

## CEO 준비 방식 잠정 채택과 A안 초안

CEO가 A 후보 준비 방식을 잠정 채택했다. 다음은 미승인 문서 초안이며 제품 규칙에 아직 적용하지 않는다.

- 첫 업적은 `scenario_victory`(시나리오 기존 승리 종료 조건 충족), `first_equipment_output`(맡은 국가의 기존 생산 시스템에서 양수 장비 산출), `first_defensive_victory`(기존 전투 종료 결과에서 맡은 국가가 방어 승리) 셋의 후보로 둔다. 원작 업적 이름·문장·수치를 옮기지 않는다.
- 업적 정의는 pack 내 `achievements/*.toml`로 ID/ko·en 이름키/기존 트리거 조건을 선언한다. 새 임의 게임 효과는 없고 업적 평가가 시뮬레이션 상태를 수정하지 않는다. 해당 조건 트리거가 이미 없는 경우 WP-13 레지스트리에 무엇을 추가할지 별도 검토한다.
- 첫 기록 범위는 로컬 서버 설치의 기본 프로필 한 개다. 계정/서버 신원 서비스는 없다. record key는 pack ID + major version + achievement ID, metadata는 획득 tick/date/scenario와 조작 국가다. 첫 획득만 기록하고 이후 이벤트는 중복 알림을 내지 않는 후보다. 모드도 자체 업적 파일이 있는 경우 같은 규격으로 평가한다.
- 기록은 `oh_server`의 사용자 데이터 폴더 JSON에 두고 sim 상태 해시에 포함하지 않는다. 저장 파일을 불러온 뒤 기존 기록을 지우지 않으며 재생/관전만으로 획득하는 것은 첫 후보에서 제외한다. 멀티플레이는 접속자가 배정받아 조작한 국가 조건만 평가한다. 여러 브라우저/사람이 동일 서버 프로필을 공유할 한계는 사용자 검토 대상이다.
- UI는 업적 목록·획득 상태·조건 설명과 최초 획득 알림이다. 아이언맨·온라인 계정·글로벌 순위·업적 삭제 UI는 추가하지 않는다.

```toml
[[achievement]]
id = "scenario_victory"
name_key = "achievement-scenario-victory"
description_key = "achievement-scenario-victory-description"
condition = { scenario_victory = true }
```

검토할 선택: 업적 셋/로컬 설치 공유 프로필, major version별 기록 분리, 관전/재현 획득 제외, 모드/멀티 적용 범위. 시험 계획은 동일 이벤트 중복·저장 후 재개·데이터 버전·타 국가 권한·관전/재현 제외·프로필 I/O 실패가 sim 진행에 미치는 영향·동일시드 sim 해시 무변경이다. 문서 단계 되돌림 비용은 낮으며 기록 key/프로필 범위를 제품에 연결한 뒤에는 기존 업적 데이터 마이그레이션이 필요하다.
