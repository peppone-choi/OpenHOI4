## 추천안과 이유

A는 기존 M0/M1의 의미와 파일을 유지하며 신규 정의가 있는 실행에서만 적용한다. 임의 기본값·숨은 자동 배분·없는 consumer의 성공을 만들지 않는다. 아래 합성 예제의 수치는 규칙 확인용 입력이며 Testland 콘텐츠 값 승인이 아니다. 모든 실제 수치 상수는 defines 또는 정의 데이터에 둔다.

### 국가 산출·배분·자원

- W2의 국가 IC·주 자원 산출·징병 대상 인구는 현재 그 국가가 **소유하는 주**에서 집계한다. 프로빈스 통제 변화만으로 W2 산출을 바꾸지 않는다. 주 소유권 변경은 다음 일일 경제 계산에 반영한다. 타국 통제 부분을 인구·시설 비율로 추정하지 않는다. 점령지 산출·협력·약탈은 후속 점령 규칙이며 이 계약의 묵시적 지원이 아니다.
- 공업 시설을 뜻하는 건물 ID·IC 단가·국가 보정과 각 법령의 보정은 데이터가 명시한다. 원장의 주별 기여·보정·최종 IC와 실제 배분값을 함께 검증한다. 누락 참조·음수·허용 범위 초과·overflow는 오류이며 수치를 0으로 대체하지 않는다.
- 안정도 `s`와 소비재 하한은 비율이다. 선택된 경제 법령의 데이터 `base`와 비음수 `instability_slope`로 `minimum = clamp(base + instability_slope × (1 - s), 0, 1)`을 구한다. `base`는 0~1, `s`는 0~1이다. Fx 원시 단위·곱셈 반올림은 기존 결정론 연산과 담당 schema/ADR에 명시한다. 법령/안정도 변경 뒤 하한을 만족하지 못하면 해당 명령·효과 전체를 거부한다. 비율을 몰래 재배분하지 않는다.
- 네 배분 비율은 각각 0~1이며 합은 정확히 1이어야 한다. 소비재 비율이 현재 하한 미만이면 거부한다. 독립적으로 곱한 네 IC의 고정소수점 잔여는 **소비재**에 귀속시켜 합계가 국가 IC와 정확히 같게 한다. 국가 IC가 0이어도 비율 계약을 검사한다. 소비재의 잔여 귀속은 생산/수출에 유리한 숨은 배분을 방지한다.
- 자원은 일일 산출 흐름으로 집계하고 W2에서는 비축 stock을 만들지 않는다. WP-15는 실제 생산 수요·충족률을 별도로 인수한다. 수출 배분 IC는 계산·표시만 하며 세계 시장 거래·대금·자원 구매가 실행됐다고 처리하지 않는다.

### 건설

- 건설 대상은 명령 국가가 소유한 주여야 한다. 건물 단계 상한·단계별 비용·프로젝트당 일일 IC 상한·슬롯 사용량과 인프라 보정은 데이터가 명시한다. 대상이 자체 인프라인 경우 그날 시작 시점의 인프라를 사용한다. 존재하지 않는 후속 철도/보급 상태를 변경하는 성공 효과를 만들지 않는다.
- 대기열 순서대로 남은 건설 IC에서 프로젝트 상한까지 배정한다. 진행도 단위는 누적 유효 IC이며 `배정 IC × 인프라 보정`만큼 증가한다. 완료에 필요한 양만 소비하고 남은 **원 IC**를 같은 날 다음 프로젝트에 넘긴다. Fx에서 완성에 필요한 원 IC는 부족하지 않도록 올림한다. 원 IC의 최소 단위 때문에 초과한 유효 진행도는 다른 프로젝트·다음 단계로 넘기지 않는다. 그 초과와 소비량은 원장에 보존한다.
- 대기 프로젝트도 슬롯과 목표 단계를 예약한다. 중복 목표·슬롯/단계 상한 위반을 enqueue에서 거부한다. 완료 뒤 건물 수준과 예약을 함께 갱신한다. 새 건물 수준은 그날 경제 산출을 소급 변경하지 않으며 다음 일일 계산에 반영한다.
- 취소는 진행도를 폐기하고 예약을 해제한다. 이미 쓴 IC를 환불하지 않는다. 일일 미사용 건설 IC는 저장·이월하지 않는다. 프로젝트 순서 변경은 명시 명령으로만 한다. 소유권을 잃은 주의 프로젝트는 자동 삭제하지 않고 소유권이 회복될 때까지 배정하지 않는다. skip된 프로젝트는 뒤의 유효 프로젝트 배정을 막지 않는다.

### 인력

- 징병 가능 총량은 현재 소유 주 인구 합 × 선택 징병 법령 비율의 정수 내림이다. 동일 인구에서 매일 총량을 새로 더하지 않는다. 국가별 `committed`와 `reserved`를 비음수 정수로 저장하고 가용량은 `max(0, capacity - committed - reserved)`이다. 초기 두 값은 신규 시나리오 입력이 명시하며 숨은 병력 수를 추정하지 않는다.
- 예약은 가용량에서 reserved로, 예약 확정은 reserved에서 committed로 이동한다. 즉시 소비는 가용량에서 committed로 이동한다. 예약 취소는 reserved를, 반환은 committed를 감소시킨다. 음수·초과 예약/반환·overflow를 전체 거부한다. WP-16의 실제 훈련/보충은 이 API를 인수해야 하며 W2에서 병력이 생겼다고 표시하지 않는다.
- 인구/징병 법령이 감소해 capacity가 committed+reserved 미만이 되어도 기존 병력·예약을 삭제하지 않는다. 가용량만 0이 되고 초과분을 조회한다. 증가 뒤에는 같은 식으로 가용량을 다시 구한다. 인구의 자동 성장·손실은 이 요청에 포함하지 않는다.

### 정치·법령·일일 순서

- PC의 일일량·상한은 데이터로 정의한다. 정상 시간 전진으로 날짜 경계를 넘을 때 한 번 지급하고 상한에서 제한한다. 생성·Pause pump·단순 조회·같은 날짜 저장/재개에는 지급하지 않는다. 음수 PC·일일량·상한·상한보다 큰 초기 PC는 로드 오류다.
- 법령은 명시 범주·ID·정렬용 단계·PC 비용·조건 AST·징병 비율/경제 하한 등 지원되는 값으로 정의한다. 선택된 동일 법령으로 다시 변경하는 명령은 거부하고 PC를 보존한다. 같은 범주의 다른 단계는 조건과 비용을 만족하면 직접 변경할 수 있으며 중간 단계 비용을 암묵적으로 더하지 않는다. 미존재 범주/법령·미지원 조건/효과·부족한 PC·조건 실패는 전체 거부다.
- PC 비용·법령·배분 하한 검사·파생 인력은 단일 transaction으로 처리한다. 변경 후 배분 하한 위반이나 overflow가 있으면 모두 rollback한다. 법령 조건은 변경 전 권위 상태에서 평가한다. 안정도/동원도 입력·변경은 0~100% 범위를 벗어나면 clamp 성공이 아니라 오류다.
- 정상 날짜 경계에서 PC 지급 → 국가 산출/하한 검증·인력 파생 → 배분·건설 → 원장 확정 → 기존 종료 조건 평가 순서다. 건설 완료 산출은 다음날부터 반영한다. 기존 예정 명령 의미 오류 소비와 일일 phase 오류의 state/queue/RNG/clock 전체 rollback을 구분한다. 이미 종료된 checkpoint에는 새 일일 처리를 하지 않는다.
- 안정도 생산 효율·항복 보정과 동원도 조직력/피로·후속 정치 행동은 실제 WP-15/20 등 consumer 인수 전까지 지원됐다고 하지 않는다. WP-14가 지원하는 정치 값·법령 조건·산업 점수 adapter만 연결하고 미지원 nonzero 효과는 기존 capability 오류로 유지한다. REQ-NAT-03·REQ-ECO-07 전체 완료를 producer 단계 증거만으로 표시하지 않는다.

## 1. 일일 순서 수정

A의 `PC 지급 → 경제`는 기존 명세와 실제 step의 순서에 충돌하므로 채택하지 않는다. 02 §6.2와 현재 Phase 순서를 유지한다: Commands → 시간/이동/전투/통제 → 날짜 경계에서 Supply → Economy → Production → Construction → ManpowerTrainingReinforcement → Research → Politics(PC 지급) → AgendaAndDecisions → Events → Diplomacy → AI → Ledger → 기존 종료 checkpoint → Snapshot. 현재 미구현 phase의 행동을 성공으로 만들지 않는다.

PC는 정상 날짜 경계의 Politics에서 한 번만 지급한다. 생성/Paused pump/조회/같은 날짜 복원에는 지급하지 않는다. 날짜 경계 틱의 Commands에서 실행되는 법령 변경은 그 명령 직전의 PC로 비용을 검사한다. 아직 Politics에서 지급하지 않은 PC를 미리 쓰게 하지 않는다. 이후 해당 날짜 지급은 새 법령/권위 상태로 진행한다. PC 지급 또는 뒤 phase 오류는 그 틱 state/queue/clock/RNG 전체 commit을 하지 않는다. 예: 경계 전 PC0·일일3·법령비용3 명령은 PC 부족 의미 오류로 소비되고 법령 불변, 정상 phase 뒤 PC3; phase 자체가 실패하면 그 소비까지 rollback한다. 전날 Pause/재개 반복으로 지급하지 않는다.

## 2. 산술·정의·인력 경계

소유 주 산출, 소비재 하한 공식, 네 비율 정확합1과 소비재 잔여 귀속, 자원 일일 흐름/수출 계산 한정, 건설 원IC 잔여/올림·초과폐기, committed/reserved 수명, 법령 변경 원자성은 A대로 채택한다. 기존 formula는 fixed checked_mul의 내림과 checked add를 사용한다. 비율/계수 Fx, 누적량 Qty, 정수 인력 i64라는 DR-01을 실제 필드별 단위·bits·허용 최대·변환/곱셈 순서 표와 ADR로 인수한다. 기존 Fx 원장에 Qty를 조용히 좁혀 넣지 않는다. 새 수량 원장을 필요하면 별도로 두고 실제 적용값과 같은 raw bits를 증명한다. 조회값을 다음 일일 산출과 혼동하지 않도록 계산 tick/주 기여 스냅샷을 노출한다.

데이터 비용은 양수, 건설 cap/슬롯 사용량/인프라 보정은 음수 거부·범위 검사다. cap0 또는 보정0이면 해당 프로젝트 배정/소비/진행0으로 skip하고 뒤 유효 프로젝트를 계속한다. 0으로 나누거나 원IC만 소모하지 않는다. 완료 양수 비용과 원IC 최소단위 ceil 경계를 독립 정수 기대값으로 검사한다. 인구합/committed+reserved/배분/보정은 checked overflow를 전체 오류로 처리하며, PC 상한 제한은 유효 입력의 덧셈이 중간 오버플로 없이 상한에 도달하도록 checked/wide 계산한다. 데이터 누락을0 또는 임의 법령으로 대체하지 않는다.

인력 예약/확정/소비/반환은 권위 내부 API이며 W2에 소비자가 없다는 이유로 플레이어에게 임의 반환/인력 생성 명령을 노출하지 않는다. 실제 consumer가 생기면 소유/프로젝트 참조·중복 확정/취소·타국 예약 변경 거부를 인수한다. 초기 capacity 미만/초과 committed+reserved 둘 다 명시 입력으로 검사하고 capacity 감소는 기존 값을 삭제하지 않는다.

## 3. 건설 예약과 소유권 경계 명시

W2 프로젝트는 한 (주ID, 건물ID)의 **현재 수준+1 한 단계**를 목표로 한다. 같은 국가의 같은 대상 건물에 활성/대기 프로젝트가 이미 있으면 다른 목표 단계로 우회 enqueue하지 못한다. 다음 단계는 이전 단계 완료 뒤 새 명시 enqueue로 예약한다. 단계별 슬롯 소비는 데이터이고 현재 건물의 실제 점유+현재 소유자가 예약한 증가량이 슬롯 상한을 넘으면 enqueue를 거부한다. 비용0/이미 완료 목표/비연속 단계를 임의 자동완료하지 않는다.

소유권을 잃은 프로젝트는 국가 queue·누적 진행도·목표·예약 기록을 보존하되 배정0/사유 `소유권 없음`으로 skip한다. 이 휴면 예약은 새 소유자의 활성 슬롯 점유로 계산하지 않는다. 회복 시 현재 수준/목표/슬롯/정의를 다시 검사한다. 다른 소유자의 건설로 목표가 이미 완료되거나 슬롯이 부족하면 자동완료/보상/삭제/단계상승하지 않고 배정0·사유 있는 휴면 상태로 남겨 명시 취소를 허용한다. 유효한 경우만 원 진행도에서 재개한다. 뒤 유효 프로젝트를 막지 않는다. 신규 소유권 변경 명령/점령 수익 자체는 W2 지원으로 추가하지 않는다.

예: A의 level0→1 진행2 프로젝트가 소유권 상실 시 보존/0배정, B 소유 동안 활성 슬롯은 B의 실제건물/예약 기준; B가 level1을 완성하고 A가 회복하면 A의 old 목표1 프로젝트는 target-conflict로 휴면·진행2보존·환불없음, 명시 취소 전까지 자동 level2를 만들지 않는다. 소유 회복/valid 슬롯의 경우에는 기존 진행도에서 재개한다. 보정0 선행 프로젝트는 뒤 cap>0·보정>0 프로젝트 배정을 막지 않는다.

## 4. 명령·효과·후속 consumer와 호환

law/category/step/PC/조건 AST 참조는 데이터. 조건은 해당 명령 직전 권위 상태에서 평가하고 동일법령/부족PC/하한실패/overflow는 해당 transaction 전체 거부다. multi-effect가 앞에서 flags/PC/법령/안정도를 바꾼 뒤 뒤 효과가 실패하면 앞 변경도 rollback한다. 기존 Command 의미 오류 소비와 whole-phase rollback을 그대로 구분한다.

지원되지 않는 조건/효과는 값0인 경우까지 기존 capability 오류를 유지한다. A의 `미지원 nonzero 효과` 문구가 zero이면 성공이라는 예외를 만들지 않게 수정한다. 실제 정치 조건/법령/산업 점수 adapter만 연결하며 안정도 생산/항복·동원도 군사 효과·인력 훈련/보충·자원 부족 생산·시장 consumer는 담당 후속 WP와 검증 기대를 추적한다. producer 자체 PASS로 NAT03/ECO04/ECO07 전체를 완료 표시하지 않는다.

새 상태·예약/휴면 사유·누적 진행·현재 법령/PC·정의 identity·계산 tick/파생 원장·pending/future queue를 DTO/canonical/hash/save/wire/repro에 같은 수명으로 보존한다. 기존 None/fixture/bytes/hash를 새0상태로 바꾸지 않는다. 새 pack 추가로 전체 content_hash가 달라지는 것은 원 frozen fixture와 별도로 검증한다. 신규 저장 읽기 경로와 명시적 version/presence 거부를 설계하되 과거저장 파괴/migration/삭제를 이 채택으로 허용하지 않는다.
