## 질문 (한 문장)

직접 이동 중 현재 프로빈스 간 edge에 진행 시간이 있을 때 정지·목적지 변경 명령은 현재 edge 도착까지 유지하는 A를 잠정 채택할 수 있는가?

01 §4.7은 거리÷속도×보정과 직접 이동을 정하지만 edge 중간의 정지·경로 변경은 명시하지 않는다. 아래는 자체 모델 후보이며 원작 자료를 쓰지 않았다. 사용자 확정 D-05 상태 변경이나 새 군사 시스템 도입 요청이 아니다. 04 §2의 기존 승인 범위 가역적 세부 후보로 CEO 검토에 전달한다.

## 선택지

| 선택지 | 플레이 경험 | 구현 비용 | 위험 |
|---|---|---|---|
| A | elapsed=0이면 즉시 정지/새 경로. elapsed>0이면 현재 edge·누적시간을 보존하고 도착 지점에서 정지하거나 새 목적지 경로를 시작한다. Pause는 즉시 시뮬레이션 시간을 멈춘다. | 현재 position=완료한 마지막 province, route/elapsed 모델 유지. 명령/저장 fixture로 경계 검증 | Stop 입력 뒤 현재 edge까지 이동한다는 의미를 향후 UI에 표시해야 함 |
| B | elapsed>0 동안 Stop/reroute를 거부하고 도착 뒤 새 명령을 받는다 | 단순하지만 별도 거부 사유/클라이언트 표시 필요 | 직접 조작이 도착 시점까지 제한됨 |

## 추천안과 이유

A. 가짜 중간 프로빈스나 순간이동·진행 비용 삭제를 도입하지 않고 기존 프로빈스 위치/경로/진행 상태를 보존한다. 최단 경로는 양수 edge 시간의 합, 동점 전체 ProvinceId 경로 lexical이다. 시간계수 계산은 Fx checked 거리÷속도→지형→인프라→보급→하천이며 exact 10km/2kmh×1.5=7.5h 사례에서 7틱 후 출발/elapsed7, 8틱 후 도착/다음 elapsed0.5다. 이 수치는 합성 검증 입력이며 콘텐츠값 승인이 아니다.

A 명령 경계: 진행 edge의 끝점부터 새 목표까지 유효 경로를 먼저 검증하고 실패하면 기존 route/elapsed/queue를 보존한다. 유효 명령 적용 시 진행 leg와 elapsed를 보존하며 뒤 경로만 교체한다. Stop 적용 시 진행 leg 하나를 남기고 뒤 경로를 비운다. elapsed0은 전환 지점이므로 즉시 중지/재탐색한다. pending 의미오류와 전체 phase 실패는 기존 atomicity 계약대로 구분한다. 새 전투·보급·통행권 효과를 정한 것이 아니다.

## 기본안으로 먼저 진행할 경우 되돌림 비용

답 전 종속 동작은 구현하지 않는다. A 잠정 채택 후 변경은 Move/Stop 처리와 그 신규 fixture/문서의 변경이다. v1 저장은 유지하며 신규 v2 route/elapsed를 보존해 미래 읽기 의미를 별도로 검토한다. 기존 저장 거부·migration·테스트 약화는 수행하지 않는다.
