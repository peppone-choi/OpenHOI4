# 후속 시스템 최소 설계 후보

2026-10-07 차량 후보 후속: [v2 운용·손실](DETAIL-DRAFT-0002-transport-v2.md)의 한정 범위를 CEO가 잠정 채택했다. 아래 차량 첫 초안은 이전 검토 이력이며 v2가 보강한 순서/재고/오류 경계를 대신하지 않는다. 실제 WP-15 계약/호환·k/r 콘텐츠 값은 검토 대기이고 다른 미완성 공식은 미승인이다.

2026-10-06, REQUEST-0002·REQUEST-0004의 A 후보 준비 방식을 CEO가 잠정 채택했다. 아래는 검토용 **미승인 초안**이다. 실제 게임 규칙으로 적용하거나 01의 확정 규칙으로 기록하지 않는다. 기존 사용자 승인 범위 안의 후보이며 수치는 자체 제안한 개발 시험값이다. 원작 데이터·규칙표를 사용하지 않았다. 모든 수치는 채택 뒤 defines 또는 장비/모듈 정의에 둔다.

## M4 차량 소모 — OPEN-03 / REQ-SUP-05 / WP-44

보급 거점별 차량 배정량을 명령으로 지정하는 후보다. 차량은 WP-15의 장비 비축/생산을 재사용한다. 필요 차량은 거점이 이번 날 공급할 용량 × trucks_per_supply_unit를 올림해 구하고, 실제 배정/필요 비율(상한 1)을 거점 처리량에 곱한다. 철도·항구의 기존 연결·용량 규칙은 그대로 입력으로 쓴다. 일일 소모는 실제 운용 차량 × daily_loss_ratio를 고정소수점 누적하고 정수 부분만 장비 비축에서 차감하며 부족하면 실제 운용량을 낮춘다. 전투 손실이나 별도 차량 이동 게임은 첫 버전에서 추가하지 않는다. 철도 궤간 변환은 제외한다.

```toml
[supply_transport]
equipment_id = "supply_truck"
trucks_per_supply_unit = 1
daily_loss_ratio = 0.01
```

검토 대상: 운용 필요량/손실 공식, 누적 소수 손실, 차량 배정 조작 유무. 시험 계획: 비축보다 많은 배정 거부, 차량0/충분/부족의 처리량, 100일 누적 소모·저장재개와 원장 일치. 되돌림 비용: 장비 비축과 거점 저장 필드가 추가되면 중간 수준(마이그레이션·경제 AI·보급 골든).

## M4 기상·계절 — OPEN-07 / REQ-GEN-07 / WP-44

지역별 계절 달력과 기상 전이 가중치를 데이터로 두는 후보다. 계절은 시나리오 날짜·지역 월별 정의만 읽으며 현실 날씨 API를 쓰지 않는다. 일일 기상은 시스템 RNG를 지역 ID·게임일로 파생해 가중치에서 하나 선택한다. 첫 유형은 clear/rain/snow 셋, 영향은 기존 이동 속도와 공군 임무 효율의 Mul 보정치 두 대상에 한정한다. 기존 타깃 계산·수치 원장을 재사용한다. 계절별 대상 지역/날짜/가중치는 콘텐츠 데이터이며 실제 역사 수치로 가장하지 않는다.

```toml
[[weather_type]]
id = "rain"
movement_mult = 0.85
air_mission_mult = 0.8
[[weather_type]]
id = "snow"
movement_mult = 0.7
air_mission_mult = 0.75
[[weather_type]]
id = "clear"
movement_mult = 1
air_mission_mult = 1
```

검토 대상: 유형·효과를 이 둘로 제한하는가, 지역/매일 단위인가, 계절은 월별 데이터인가. 가중치·지역 매핑은 다음 후보 데이터에서 제시한다. 시험 계획: 지역/날짜별 RNG 재현, 0가중치 오류, 기상 효과 원장, 플랫폼·저장재개 동일성. 되돌림 비용: 미구현 단계 낮음; 후속 지역 상태/저장과 이동·공군 골든 변경 필요.

## M4 저항·준수 — OPEN-08 / REQ-ECO-09 / WP-42

점령 주별 resistance/compliance의 Fx [0,1] 상태와 정책 선택 명령을 두는 후보다. 정책은 civilian/military 두 개로 시작한다. 주 원래 소유자와 현재 통제자가 다를 때만 일일 정책 델타를 적용하고 범위를 clamp한다. 산출의 통제국 귀속 비율은 occupation_base_share + compliance × occupation_compliance_share로 정한 뒤 resistance × occupation_resistance_penalty를 Mul로 적용한다. 인구·장비 소모/진압 부대 같은 새 제도는 첫 후보에서 제외한다. 반환되면 점령 상태의 처리(초기화/보존)를 검토해야 한다.

```toml
[occupation]
base_share = 0.25
compliance_share = 0.5
resistance_penalty = 0.5
[[occupation_policy]]
id = "civilian"
daily_compliance_delta = 0.002
daily_resistance_delta = -0.001
[[occupation_policy]]
id = "military"
daily_compliance_delta = 0.001
daily_resistance_delta = -0.003
```

검토 대상: 두 정책의 비용/효과 균형(현재 비용 없는 military 우위가 생길 수 있어 비용 제안이나 효과 수정이 필요), 주별 상태/산출 식, 반환 처리. 이 후보를 현재 형태 그대로 구현하면 정책 선택이 의미 없을 위험을 먼저 기록한다. 시험 계획: 상태 경계·비점령 미적용·반환·서버 소유권 거부·원장 일치. 되돌림 비용: 경제 산출·AI·주 저장과 골든에 연결되므로 중간 이상.

## M4 첩보 — OPEN-08 / REQ-NAT-08 / WP-42

국가별 intelligence_budget을 PC 지출로 충전하고 target nation별 정보망 수치[0,1]를 올리는 후보다. 첫 행동은 build_network와 disrupt_production 둘로 제한한다. 정보망 구축은 확정 일일 성장, 방해는 정해진 소요 게임일 후 system RNG로 판정해 대상 산업의 기간 제한 Mul 보정치를 넣는다. 전장의 안개를 추가하지 않으며 정보망으로 새 숨김 정보를 강제하지 않는다. 외부 통신/현실 정보 수집을 사용하지 않는다.

```toml
[intelligence]
network_build_days = 30
mission_cost_pc = 25
disruption_days = 7
disruption_production_mult = 0.9
```

검토 대상: PC로 자원 통합, 행동 둘과 성장/성공 확률 공식(확률은 아직 제시 안 됨), 최대 동시 임무 수·대상 권한, 정보망을 방해 조건에 쓰는가. 성공 확률·임무 슬롯까지 승인돼야 구현 가능한 후보로 완성된다. 시험 계획: 자원/대상/권한 검사·취소/완료·동일 RNG·만료와 원장·저장재개. 되돌림 비용: 임무 저장·명령·PC·AI 연결로 중간 이상.

## M5 차체·모듈 장비 — OPEN-01 / REQ-MIL-11 / WP-48

첫 대상은 지상 기갑 장비로 제한하고 chassis + weapon + armor + engine의 슬롯 셋을 두는 후보다. 각 슬롯은 허용 module_id를 정확히 하나 가지며 모듈이 제공하는 장비 stats Add를 차체 기본값에 합산한다. 장비 단가/자원 비용도 차체 기본+모듈 합으로 계산하고 생산 라인에는 설계 ID/버전을 고정한다. 변경은 새 설계 버전 생성이며 이미 생산된 비축을 소급 변환하지 않는다. 연구가 해제한 모듈만 사용한다. 함선 설계로 확장하지 않는다.

```toml
[[chassis]]
id = "synthetic_land_chassis_1"
slots = ["weapon", "armor", "engine"]
[[module]]
id = "synthetic_engine_1"
slot = "engine"
unit_cost = 1
stats_add = { speed_kmh = 1 }
```

검토 대상: 첫 대상/슬롯 수·조합 규칙·능력치 합산·구형 비축 유지·생산라인 전환 연결. 샘플은 전체 실제 밸런스 표가 아니며 나머지 모듈·기술·비용을 별도 제시해야 한다. 시험 계획: 슬롯 중복/누락·미해금·참조·raw Fx 합산/원장·설계 버전 보존. 되돌림 비용: 장비 정의/저장/생산·연구 UI 연결로 높음; 버전 고정으로 소급 변경 범위를 줄임.

## M5 공군 임무 — OPEN-04 / REQ-AIR-03 / WP-48

기존 air_superiority/close_support에 strategic_bombing과 intercept_bombing을 추가하는 후보다. 전략 폭격은 공역에서 선택한 적 통제 주의 산업 건물 손상량을 일일 고정소수점으로 누적하고 정수 레벨 차감만 건설 시스템에 전달한다. 요격은 전략 폭격 효과에 배치 전투기 전력비 기반 Mul을 적용하는 후보이며 부대 손실은 별도 기존 공군 전력 규칙과 함께 검토해야 한다. 산업·인프라·항구 중 첫 대상은 산업만으로 제한한다.

검토 대상: 임무 네 종류, 목표/공역 소유권, 건물 손상/수리 규격, 요격과 기체 소모 공식. 기체 손실/폭격 계수는 아직 제시 안 됐으므로 임의 구현하지 않는다. 시험 계획: 적대 대상 거부·손상 누적/수리·중복 목표 분배·원장/플랫폼·저장재개. 되돌림 비용: 공군/건설·저장/AI/임무 UI 연결로 중간 이상.

## M5 함대 전투 — OPEN-05 / REQ-NAV-04 / WP-48

함선 개별 설계 없이 데이터 고정 ship_model과 모델별 fleet 수량을 쓰는 후보다. 같은 해역의 적대 함대는 매일 한 번, 함대 ID 순으로 결집한 공격/방어 전력을 계산한다. 피해는 ratio 기반 결정론 수식으로 모델별 손실 누적량에 반영하고 최소 전력 조건 이하이면 인접 우호 항구로 퇴각한다. 함대 우선순위/피해 분배/피해 계수/퇴각 조건은 후속 세부값 검토 대상이다. 실제 함선 설계는 시점 미정 이후 로드맵에 보존한다.

검토 대상: 일일 집계 전투, 모델별 수량/손실, 피해·대상 분배·퇴각 규칙, 기존 해역통제/호송 연결. 시험 계획: 함대 순서·0전력·적대 판정·퇴로없음·개별모델 loss clamp·동일시드/저장재개. 되돌림 비용: fleet 상태·해역 결과·AI·저장·골든으로 높음.

## M5 특수 무기 — OPEN-11 / REQ-MIL-12 / WP-48

실물 기술 설명 없이 게임 데이터의 special_weapon_model·연구 해제·생산 비축·사용 명령만 다루는 후보다. 첫 효과를 전투 조직력 감소와 주 건물 손상 두 데이터 효과로 제한하고 명령은 적대 대상·연구/비축·사용 조건을 서버에서 검증해 비축 한 개를 소비한다. 사용 가능 플랫폼/사거리/쿨다운/피해 수치는 별도 사용자 검토 대상이며 미정 상태다. 현실 무기 제조·운용 정보는 데이터에 넣지 않는다.

검토 대상: 실제 포함할 무기 종류/사용 조건, 효과 대상·비축 소비·사용 빈도, AI 정책. 시험 계획: 무비축/미해금/비적대 거부·단일소비·동일 명령 재전송·원장·저장재개. 되돌림 비용: 연구/생산·명령/AI·주·부대 상태로 중간 이상.

## 채택 범위와 준비 우선순위

CEO가 가역적 후보 준비를 잠정 채택할 수 있으며 이 파일의 모든 세부 규칙이 채택된 것은 아니다. 현재 미완성 공식/값이 명시된 후보는 관련 시스템 착수 전 완성해 재검토해야 한다. M1 구현·검증·통합을 우선하고 M4 후보부터 순차 확정한다. 되돌림 비용은 문서 단계 낮음과 제품 연결 이후 비용을 구분한 상대 평가다.
