### 추가 검증 helper의 실패·수정 근거

- continuity 첫 단언은 wheel 이벤트가 적용되기 전에 카메라를 저장해 실패했다. zoom 변경을 먼저 기다리도록 helper를 수정했다. 최초 `continuity.log`와 최종 결과 모두 보존했다.
- HTTP oracle 첫 단언은 FNV hex의 선행 0을 빠뜨렸다. 계약의 16자리 lowerhex 표현에 맞춰 수정했다. `http-independent.log` 보존.
- 최초 CORS fixture는 Playwright route가 redirect chain의 첫 URL만 처리해 **최종 응답 ACAO 주입이 실행되지 않았다**. 따라서 “valid CORS를 제공했으므로 렌더될 것”이라는 fixture 전제가 잘못됐다. frame 대기 실패 로그는 `http-independent-final.log`에 보존했다. 이후 CORS 미허용 거부와 다른 origin GET 관측을 별도로 기록했으며, 이를 애플리케이션 origin 보호 PASS로 사용하지 않았다.
- 이를 바로잡은 아래 CDP fixture는 두 요청을 각각 포착하고 최종 CORS 응답을 실제 제공한다. **계약상 기대인 거부를 유지한 채 FAIL**했다.
- 확대 선폭 helper의 최초 엄격한 순서 단언은 정수 래스터 위상에서 1.2px/2.8px 선이 각각 2픽셀로 샘플링돼 실패했다. 계약의 milli CSS 단위로 도출한 명목 폭과 ≤1픽셀 래스터 오차를 검사했다. 최초 `zoom-border.log`와 최종 로그·이미지를 보존했으며 기존 추적 테스트는 변경하지 않았다.
