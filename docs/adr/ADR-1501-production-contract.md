# ADR-1501 — Production authority and additive save contract

Status: implementation candidate, 2026-10-08. User approved fractional equipment carry, productive-day growth, different-model partial discard and proportional resource allocation, and delegated data-driven provisional tuning. Independent verification and integration remain pending. Alternatives in the earlier preparation are not adopted.

WP-15 implements REQ-ECO-03 and equipment inventory portion of REQ-MIL-01. Economy supplies military IC as Qty, resource flow as i64 units/day and stability as Fx. Production executes after Economy and before Construction at midnight. No resource stocks, research/combat/division/vehicle consumers are advertised.

## Fields and lifetime

Production is explicitly selected by `scenario.production` and loaded from `common/production/<id>.toml`. Models use registry string IDs/family, u32 generation, localized name key, positive Qty IC-days/item and positive Qty resource units/item. Each nation explicitly declares allowed models and whole initial stock. Tunables are required `defines.production` values, never implicit zeros. Existing absent systems and frozen packs stay absent.

Private production authority contains definition hash, monotonic next u64 line ID, sorted lines (nation/model/requested Qty IC/paused/Fx efficiency/Qty partial item), sorted nation/model i64 available stock, last daily ledger and current command-discard journal. Zero numeric IDs are valid. Carry is0<=carry<1; efficiency isinitial..cap; inventory is nonnegative within the data safety bound. All references and ticks are validated before restore. The daily tick must equal the latest elapsed midnight, its line IDs are globally unique and capped, and its stored inputs recompute the exact output journal. It can retain a line subsequently cancelled by a command. Scheduled intents for already allocated but cancelled IDs remain queued and later fail semantically; IDs never allocated and live foreign-owned references are rejected. Definitions reload from the matching pack; no untrusted saved definitions.

These live fields and exact ledgers enter canonical/hash, additive save v6, read-only query and generated TS. Fixed values carry canonical decimal raw i64 strings and fractional bit counts16/32; resource aggregate raw sums use bounded i128 decimal strings without Qty→Fx narrowing or JS-number conversion. UI displays the stored authority, never computes game formulas.

## Provisional synthetic tuning

Initial efficiency0.25, cap1, growth0.0078125 (=1/128) per actual-production day:96 productive days to cap from initial. Same-family strictly newer retention0.75; other different-model retention0.25. Switching retains at least initial efficiency and discards old carry; same model preserves all. Stability output multiplier is linear0.5..1.5, hence1 at stability0.5. These are independently selected binary-friendly provisional values, not borrowed game balance. Half/double growth sensitivity gives192/48 productive days; stability endpoints halve/increase output by50%, without changing stored line efficiency. Required inventory_count_limit=9223372036854775807 and lines_max=1024 govern arithmetic/memory, not warehouse mechanics. All nine keys are read from defines.production; baseline values are present only in the new synthetic input fixture, not injected into frozen packs.

Pre-growth output uses floor in order IC×efficiency, then stability, then unit-cost division into Qty equipment equivalents. Requested IC above current budget is rejected on settings; existing requests scale proportionately after a budget decrease. Every proportional split uses floor/largest fractional remainder, ID only breaks a raw-quantum tie. Wide exact multiply/divide handles1024 maximal raw demands without an overflowing intermediate product; whole output/carry accumulate in i128 before the checked i64 stock update. Assigned IC is not reassigned after resource shortage.

Resource demand is conservative ceil(output×per-item cost) in raw Qty resource units. Each resource shares current i64 daily flow proportionately; line fulfillment is minimum reserved/demand ratio, absent requirements give1. Actual debit is ceil(actual fractional output×cost) and must not exceed reservation. Another resource bottleneck leaves unused resources that day: no redistribution, stock or carry of resource flow. Fractional item output carries across days/pause/save, completed whole items enter inventory; only representably positive output grows efficiency. Overflow in any phase rolls back the entire step.

## Save and failure boundaries

None/v1–v5 bodies/enums/bytes/hash remain frozen. v6 wraps frozen v5 state with its nested queues empty, a complete new ordered queue and explicit production authority; economy is a prerequisite. Old writers remain selected when production is absent. New presence is never injected into historical saves. New bounded preflight validates entries/strings/raw widths before authority construction. Future supply changes must extend the accepted v6 contract separately.

Enqueue previews clones. A consumed scheduled semantic command rejection differs from whole-phase failure: a successful step consumes/report rejects and advances time; phase failure preserves clock/queue/world/economy/production/RNG. Stock/carry/output/efficiency/ledgers commit together. Cancel/model switch journals retain discarded partial progress at the command tick. A missing downstream effect remains unsupported even amount0.

WP-19 may rely on whole available equipment counts, model IDs and fixed production scheduling, but supply demand/strength/rails and WP-44 vehicle reservation/total-bound/k/C scaling are not invented here. This ADR is a contract candidate until implementation and independent verification establish it.

## Interface map

- Data: `oh_data::production::{Definition,Model,NationInput,Tuning}`; `LoadedNational.production` and immutable `World::defs().production()` reload explicit inputs. The separate production identity hashes models, nation input and tuning, preserving the old world identity tuple.
- Authority: `Simulation::production()` is read-only; commands enter the common ordered queue as `Command::Production(Action::{Create,SetIC,Pause,Switch,Cancel})`. Line IDs start at0, advance on successful creation and are never reused. `Production::adjust_stock` is a trusted checked inventory operation used by the producer; no player stock-minting command exists.
- Save: `SimulationSaveV6 { base: SimulationSaveV5, queue: Vec<PendingV6>, production: Production }`; `CommandV6::{Legacy,Production}` contains every pending intent. The frozen nested V5 queue must be empty. Normal and forced decoding require matching production presence and validated authority. Force can permit a pack content hash mismatch with a warning; it cannot invent absent production or bypass definition identity.
- Wire/runtime: `ProductionCommand` carries canonical u64/i64 raw decimal strings; `ProductionResult` answers query kind production. `ProductionView` exposes model costs, allowed-model stock, current requested military budget, lines, latest exact daily calculation, discarded carry and pending intents. Missing required resource flow is explicitly projected as zero. Generated TS and strict guards retain16/32 fractional bits and i128 aggregate widths.
- Browser: nation selection opens a new local connection with that initial Join selection. Existing second-Join rejection remains. Each local connection owns an independent simulation; selecting a nation starts/restores that connection's session. Controls send commands and show stored IC/efficiency/carry/stock/fulfillment and resource required/reserved/debited values. This is not a shared multiplayer or reconnect-persistence contract.

Synthetic controls use equipment model IDs only; the initial M2 geography pack remains an economy-only pack without final equipment, rail, OOB or downstream consumers.
