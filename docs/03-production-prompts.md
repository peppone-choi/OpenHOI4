## 0. 구성과 사용법

### 0.1 이 문서와 함께 쓰는 파일

| 파일 | 역할 |
|---|---|
| `AGENTS.md` | 모든 Codex 세션이 자동으로 읽는 규칙. 역할별 규칙(§0, §4, §5)이 들어 있어 프롬프트마다 규칙을 반복하지 않는다 |
| `tools/orch.sh` | 오케스트레이터가 구현·검증 세션을 만들고 상태를 보는 도구(02 §12.4) |
| `docs/templates/*` | 작업 로그, 검증 리포트, 인수인계, ADR, 결정 요청 양식 |

### 0.2 흐름

```
[사용자] Codex 세션 시작 → P-01 붙여넣기 (이 세션이 오케스트레이터)
   │
   ├─ P-02 마일스톤 실행 ─ P-04 병렬 분담 계획
   │     ├─ orch.sh start impl   ← P-03 구현 / P-11 콘텐츠 / P-06 수정   (병렬, 각자 worktree)
   │     ├─ orch.sh start verify ← P-05 독립 검증                         (구현 끝나는 대로)
   │     ├─ P-07 통합 (PASS인 것부터)
   │     └─ P-10 결정 요청 (미결정 규칙을 만났을 때, 모아서 한 번에)
   ├─ P-12 게이트 판정 → 다음 마일스톤 P-02
   └─ 세션 종료: P-08 인수인계 → 새 오케스트레이터 세션: P-09 재개
```

| `{{HANDOFF_PATH}}` | 인수인계 파일 | `HANDOFF.md` |

### 0.4 공통 원칙 (본문은 AGENTS.md)

1. **병렬화**: 병렬로 할 수 있는 WP는 세션을 따로 만들어 동시에 진행한다.
2. **오케스트레이터도 일한다**: 세션들이 도는 동안 오케스트레이터는 자기 작업을 한다. 기다리기만 하지 않는다.
3. **구현과 검증 분리**: 검증은 구현에 참여하지 않은 새 검증 세션이 한다. 검증 세션이 파일을 바꾸면 무효다.
4. **증거 기반 완료**: 완료는 실제 검증 증거로만 판정한다(02 §15).
5. **질문 방식**: 질문은 착수 시 한 번에 모아서 한다. 막힌 부분이 있어도 나머지는 끝까지 하고, 못 한 부분은 이유를 따로 보고한다.
6. **사전 확인**: 복구하기 어려운 삭제, 요청 범위 변경, 샌드박스·네트워크 설정 변경은 먼저 묻는다.

### 0.5 세션 만드는 법 (오케스트레이터용 요약)

```
# 1) 프롬프트 파일 작성: P-03/P-05/P-06/P-11 본문의 변수를 채워 저장
.orchestrator/prompts/WP-14.impl.md
# 2) 분리 실행 — 같은 묶음의 WP는 연달아 시작
tools/orch.sh start impl   WP-14 wp/14-economy .orchestrator/prompts/WP-14.impl.md
tools/orch.sh start impl   WP-17 wp/17-movement .orchestrator/prompts/WP-17.impl.md
# 3) 자기 작업을 하면서 사이사이 확인
tools/orch.sh status
# 4) 구현이 끝난 WP는 바로 검증 세션
tools/orch.sh start verify WP-14 wp/14-economy .orchestrator/prompts/WP-14.verify.md
# 결과: .orchestrator/out/<WP>.<impl|verify>.last.md, .exit
```

## P-01 최초 착수

| 항목 | 내용 |

```text
[2단계 — 병렬]

- WP-03 (P-03)
```

## P-03 WP 구현 (구현 세션 프롬프트)

| 항목 | 내용 |
|---|---|
| 사용 시점 | 코드 WP 하나를 구현 세션에 맡길 때 |
| 실행 주체 | 오케스트레이터가 작성하고, `orch.sh start impl`로 만든 Codex 구현 세션이 수행 |
| 입력 변수 | `{{WP_ID}}`, `{{BRANCH}}`, `{{WORKLOG_PATH}}` |
| 완료 조건 | 작업 로그에 증거 E1·E2(필요하면 E3~E5)가 있고 브랜치에 커밋됨. 완료 판정은 검증 세션 몫 |

```text
역할: 구현 세션. 너는 OpenHOI 구현 세션이다. 작업 패키지 {{WP_ID}}를 구현한다.
현재 폴더는 이 WP 전용 git worktree이고, 브랜치는 {{BRANCH}}다.
비대화형 세션이라 질문할 수 없다. 막히는 것은 작업 로그에 적고 나머지를 진행한다.
AGENTS.md §2(절대 규칙)와 §4(구현 세션 규칙)를 따른다.

[범위]
- docs/02-production-spec.md §12.2의 {{WP_ID}} 행이 범위다. 대상 REQ, 선행 WP, 완료 증거를 확인한다.
- 대상 REQ의 정의는 01 §8, 규칙은 01 §4, 기술 규격은 02의 해당 절이다.
- 서버와 클라이언트를 함께 건드리는 WP라면 프로토콜 타입은 oh_proto에만 정의한다. TS 타입은 생성물을 쓴다.
- 신규 시스템·스키마 변경 전 02 §5.11과 docs/plans/schema-planning.md에 따라 docs/plans/{{WP_ID}}-schema.md 또는 해당 ADR에 필드/참조/권위/해시·저장/wire·UI와 독립 경계 예제를 설계한다. 실제 문서 경로와 누락 대조를 작업 로그에 남긴다. 현재 기초 모델과 후속 미구현 필드를 구분한다.
```

```text
추측한 상태를 적지 않는다. 확인한 것만 쓰고, 확인하지 못한 것은 "미확인"으로 표시한다.
```

## P-11 콘텐츠 제작 (구현 세션 프롬프트)

| 항목 | 내용 |
|---|---|
| 사용 시점 | 콘텐츠 WP(WP-23, WP-33, WP-38, WP-45)나 그 일부 |
| 실행 주체 | 오케스트레이터가 작성하고, `orch.sh start impl`의 구현 세션이 수행 |
| 입력 변수 | `{{WP_ID}}`, `{{CONTENT_SCOPE}}`, `{{BRANCH}}`, `{{WORKLOG_PATH}}` |
| 완료 조건 | `oh validate --deny-warnings` 통과, 출처 기록, 작업 로그 커밋 |

```text
역할: 구현 세션(콘텐츠). {{WP_ID}}의 범위 중 "{{CONTENT_SCOPE}}"를 데이터 팩으로 작성한다. 브랜치: {{BRANCH}}.
비대화형 세션이다. AGENTS.md §2와 §4를 따른다.

[클린룸 — 반드시 지킬 것]
- 원작 게임의 파일, 스크립트, 현지화 문장, 이미지, 프로빈스 지도는 열어보지도, 베끼지도, 따라 그리지도 않는다.
- 위키 문장을 복사하지 않는다. 사실을 참고했다면 자체 문장으로 쓴다.
- 원작의 의제·이벤트 이름과 구성을 재현하지 않는다. 역사적 사건을 다루더라도 구성과 문장은 새로 만든다.
- 국기는 대체 디자인이다. 위헌 단체 상징을 쓰지 않는다(01 §7).

[작성 규칙]
- 형식은 02 §5를 따른다.
- 수치는 공개 사료에서 가져오고, 출처를 해당 팩의 SOURCES.md에 남긴다(항목, 값, 출처, 확인일).
- 사료로 정할 수 없는 밸런스 값은 출처 칸에 "밸런스 잠정"이라고 쓴다.
- 이미지 에셋은 assets/ASSETS.toml에 등록한다. OPEN-09 사용자 결정에 따라 AI 생성 이미지는 ai_generated=true와 출처·생성 도구·이용 조건·배포 검토 증거를 기록한다. 배포 검토를 통과한 경우만 포함을 허용하며 현재 공개 배포 승인을 뜻하지 않는다.
- 화면 문자열은 모두 ko·en 현지화 키로 쓴다.

[절차]
1. oh validate --deny-warnings <팩>을 통과할 때까지 고친다.
2. 시나리오 콘텐츠라면 아래를 실행해 크래시가 없는지 확인하고 결과를 기록한다.
   - oh run --scenario <id> --days 365 --seed 1
   - oh ai-bench --runs 5
3. {{WORKLOG_PATH}}를 작성하고 커밋한다.

[마지막 메시지]
- 추가한 파일
- 검증 결과
- 출처를 정하지 못한 항목
- 못 한 부분과 이유
```

## P-12 마일스톤 게이트 판정

| 항목 | 내용 |
|---|---|

| 실행 주체 | 오케스트레이터가 증거를 모으고, 새 검증 세션이 판정 |

| 완료 조건 | `docs/gates/{{MILESTONE}}.md`에 AC별 판정 기록 |

```text
[오케스트레이터 부분]
역할: 오케스트레이터. {{MILESTONE}} 게이트를 준비한다.
1. docs/01-game-design.md §10에서 {{MILESTONE}}의 AC-{{MILESTONE}}-NN을 모두 나열한다.
2. 각 AC의 증거를 기본 브랜치 최신 커밋에서 다시 만들거나 링크한다: CI 링크, 리포트 경로, 스크린샷.

4. 기본 브랜치 최신 커밋을 가리키는 게이트 브랜치({{BRANCH}}, 예: gate/{{MILESTONE}})를 만든다.

[검증 세션 부분]
역할: 검증 세션. {{MILESTONE}} 게이트를 판정한다. 브랜치 {{BRANCH}}. 파일을 수정하지 않는다.

  - 다음 마일스톤에서 차단될 OPEN 항목
```
