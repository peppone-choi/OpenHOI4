## 충돌과 통합

WP-02는 oh_core, WP-03은 oh_data를 소유한다. 공통 Cargo.toml/Cargo.lock 충돌은 구현 세션이 필요 변경만 남기고, 의미 판단이 필요한 충돌은 P-06으로 보낸다. 통합 순서는 WP-01 → WP-02 → WP-03 → WP-06 → WP-04 → WP-05이다. WP-02·WP-03은 각각 구현 종료 즉시 독립 검증을 시작한다. 동시 구현은 최대 두 채팅이다.

## 오케스트레이터의 동시 작업

- M0-W1: 클린룸 점검표, 환경·버전 ADR, WP-02·WP-03 프롬프트를 준비한다.
- M0-W2: WP-06 문서를 정리하고 WP-04 프롬프트 및 명령 순서 검증 항목을 확인한다.
- M0-W3: WP-05 프롬프트와 프로토콜 메시지 목록을 정리한다.
- M0-W4: 기본 브랜치 CI 로그, 각 REQ 검증 리포트, 해시 아티팩트와 UI 캡처를 모아 게이트를 준비한다.

## 실행 경로와 환경 시험

`tools/orch.sh selftest`는 실제 하위 Codex CLI에서 실패했다. `gpt-6.1-sol`이 ChatGPT 인증에서 지원되지 않는다는 HTTP 400이 원인이다. `start impl WP-00 orch/selftest`도 실행했고 다음 명령의 status에서 `done 1`을 확인했다. `done 0`으로 기록하지 않는다. runner가 별도 명령 뒤에도 살아 있었으므로 분리 실행 생존은 확인했으나, 실제 CLI 작업 성공은 확인하지 못했다.

사용자는 실패 질문에 “현재 앱 설정으로 별도 채팅을 만들어 진행”을 선택했다. 이에 앱 create_thread의 전용 worktree 채팅을 사용한다. CLI 모델·인증·샌드박스 설정을 수정하지 않는다. 각 구현 채팅은 P-03, 새 검증 채팅은 P-05를 받으며, 원래 CLI status와 앱 상태는 구분해서 기록한다. 자동 worktree 생성은 대기 상태였으므로 Git으로 만든 전용 worktree를 local 앱 채팅에서 명시한다. 앱 호출 시험은 정상 종료했고 CLI 시험 worktree와 orch/selftest 브랜치를 삭제했다. 앱 시험의 실제 상태·채팅 ID는 환경 ADR과 HANDOFF에 추가한다.

앱 검증에서는 전후 Git HEAD와 추적 파일 diff/status를 오케스트레이터가 직접 비교한다. 추적 파일 변경이나 커밋이 발생한 검증은 무효로 하고 새 검증 채팅을 만든다. CLI의 자동 exit 4를 앱 검증 성공 증거로 주장하지 않는다.

## 완료와 결정 의존

게임 규칙에 대한 착수 질문은 없다. 잠정 결정을 그대로 적용하며 D-10·D-12·OPEN 항목을 임의 확정하지 않는다. 제품 공개·라이선스 확정은 M0 범위가 아니다. WP 완료는 구현 증거, 독립 검증 PASS, main CI 녹색을 모두 확인해야 한다. CI가 없거나 실패하면 통합 커밋이 있어도 완료로 판정하지 않는다. 공개 저장소 표준 러너로 CI를 실행하고 macOS도 매 푸시 검증한다.

## 사용자 추가 지시 (2026-10-06)

README와 저장소 설명은 한국어 게임 소개 중심으로 작성한다. 사용자는 개발 완료 시 docs/, tools/, AGENTS.md를 삭제하도록 지시했다. 현재 요청의 M0는 게임 개발 전체의 기반 단계이므로 최종 개발 완료(M6 이후) 시 정리하는 지시로 적용한다. 진행 중에는 운영·검증 자료를 유지하며 마지막 정리 전에 검증 증거를 Git 이력/CI 아티팩트에 보존하고 필요한 빌드/CI 도구 참조를 정리한다. 삭제를 위해 CI 검사를 끄거나 게임 기능을 없애지 않는다.
