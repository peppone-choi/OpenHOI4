## 충돌 방지와 통합 순서

W1은 oh_data / oh_sim / client로 분리한다. root Cargo.toml·Cargo.lock·ASSETS.toml은 각 WP의 필요한 항목만 수정하고 통합 순서는 WP-07 → WP-10 → WP-12다. 숫자 계수는 defines, 새 문자열은 ko/en 키로 둔다. 제품 판단이 필요한 충돌은 구현 세션 P-06에 넘긴다.

W2는 표상 병렬 묶음이지만 oh_proto·oh_server·App 연결 충돌을 피하려고 WP-09를 먼저 구현·검증·통합하고 그 HEAD에서 WP-08을 시작한다. WP-08의 렌더링 설계와 프롬프트 준비는 WP-09 동안 오케스트레이터가 한다. 묶음 통합 횟수는 W2의 두 WP가 모두 통합된 뒤 1회로 계산한다. 완전한 경제/외교 UI인 WP-22 범위를 추가하지 않는다.

AC-M1-03의 국가/주 정보 패널은 WP-09, 기본 원장 계산은 WP-10, 원장 툴팁 표시 기본형은 WP-12, 지도 선택 연결은 WP-08이 맡는다. 실제 숫자는 서버 조회값을 표시한다. 수치 원장 최종값과 실제 적용값의 비트 일치를 서버에서 검사한다.

M0 빈 예제 팩·코어/시뮬레이션 골든은 보존한다. WP-07이 M1 Testland 지도 데이터, WP-09가 M1 시나리오·국가 상태 로드와 서버 실행 경로, WP-08이 HTTP 지도·브라우저 표시를 연결한다. Testland 6개국 완결 게임 콘텐츠(WP-23)를 미리 만들지 않는다. 최소 합성 국가·지형 데이터는 이 M1 요구를 검사하는 데 필요한 범위다. 아직 없는 validate/golden/repro 명령을 실행했다고 기록하지 않는다. 골든 기대값 변경에는 기존 규칙의 update --reason 절차를 충족하거나 막힌 사유를 기록한다.

## 실행·검증 경로

사용자가 지정한 앱 create_thread/send_message_to_thread/wait_threads를 쓴다. 프로젝트 local 채팅의 기본 cwd는 main일 수 있으므로 Git으로 만든 E:/openhoi/.orchestrator/wt/WP-NN 전용 경로를 모든 명령 workdir/Git -C와 파일 절대 경로에 강제한다. 동시 구현 최대 3개. 구현은 자기 브랜치 커밋까지만 하고 새 검증 채팅은 해당 정확한 커밋을 detached 전용 worktree에서 검사한다. 서로 다른 채팅·worktree를 통해 구현/검증을 분리한다.

검증 전후 오케스트레이터가 HEAD·index·추적 목록·각 SHA256·diff/status를 비교한다. 추적 파일 변경은 무효이며 새 검증 채팅을 만든다. 검증 리포트 전문은 마지막 메시지로 받고 오케스트레이터가 docs/verify/에 저장한다. 구현 종료 즉시 검증을 시작하며 독립 PASS 전 병합하지 않는다. 앱 turn 상태/실제 명령 종료 코드를 기록하고 앱 종료를 CLI exit 0으로 쓰지 않는다. 과거 WP-00.impl done 1은 보존한다.

새 checkout은 npm ci → npm test(원장 fixture 생성) → client build → Rust fmt/clippy/test 순서다. 관련 CLI 해시 2회, REQ별 실패→통과 기록, TS 생성 최신 여부, 라이선스·ASSETS 검사와 실제 서버 UI 캡처를 확인한다. 실제 서버 E2E의 정상·malformed 캡처 출력은 환경 변수로 ignored target에 지정해 추적 증거를 덮어쓰지 않는다. 통합 후 P-07 로컬 검사·check_docs와 main push·동일 HEAD CI 세 종류 success까지 확인한다.

## 추가 품질 검토와 직접 플레이

사용자 추가 스키마 지시: 남은 WP-08 HTTP/인덱스 계약과 이후 WP-11 저장 경계는 [스키마 기획](schema-planning.md)에 따라 구현 전에 필드·의미·단위·범위·참조·권위·버전·해시/저장/wire/UI·독립 경계 예제를 설계한다. 기존 W1/WP-09 PASS는 보존하고 M1 기초 DTO를 최종 전체 스키마로 주장하지 않는다. 위키 본문 열람 실패와 정상 확인한 기술 문서는 [조사 기록](../research/schema-source-review.md)에 남겼다.

사용자 요청에 따라 모듈 책임·실패 시 상태 보존·독립 기준 계산·경계값과 잘못된 입력을 독립 검증에서 대조한다. 도구 하나로 모든 DR 위반을 탐지했다고 주장하지 않는다. M1 신규 국가/주 상태는 M0 빈 예제 결정론 검사와 별도로 실제 해시·재개 경계에 포함되는지 WP-09/11에서 확인한다. WP-09 프로토콜 변경 때 정상 MessagePack이지만 타입/필드가 잘못된 입력도 실제 수신 경계에서 검사하고 발견 버그는 해당 구현 세션에 재현으로 배정한다. 전역 하네스·강제 자동 리뷰를 활성화하지 않는다.

WP-08의 실제 지도 연결이 열리면 전체 M1 게이트를 기다리지 않고 현재 정확한 커밋·실행 명령·로컬 URL·캡처와 미완료 범위를 CEO에 전달한다. 지도 모드/선택·호버/국가·주 패널/시간5단계/언어/원장 툴팁을 직접 브라우저 UI로 탐색하며 자동 E2E와 구분한다. 저장 UI가 실제 구현된 뒤에는 저장·재시작·이어가기 동선도 확인한다. 원시 상태를 직접 수정하여 플레이했다고 쓰지 않는다. 기록에는 시나리오/시드/날짜/환경/행동/기대·실제·스크린샷/결함을 남긴다. M2는 Testland 평시→전쟁→항복, 후속 마일스톤은 기존 플레이 AC로 확장한다.

지리 자료는 제작 단계에서 고정 로컬 파일로 보존하고 게임/지도 표시에서는 동봉 팩·자체 HTTP만 사용한다. WP-08 브라우저 요청을 검사해 외부 지리 API·타일 서버·CDN 요청 없음과 누락 파일 명확한 실패를 확인한다. OS 네트워크·샌드박스 설정을 바꾸지 않는다.

## 결정과 종료 지점

D-10·D-12는 직접 사용자 답변으로 확정됐고 REQUEST-0001에 기록했다. OPEN 일괄 기본안 승인은철회됐으며 대신 OPEN-01~12의 개별 사용자 답변을 반영했다. 기능 포함 방향과 세부 규칙 승인은 구분한다. 아직 답변 없는 세부 규칙은 구현하지 않는다. M1을 막는 OPEN은 없다. 비용·설정 변경·미병합 자료 삭제·공개 배포·태그는 하지 않는다. 이름 확정을 상표 법적 검증 완료로 기록하지 않는다.

M1-r1은 M1 게이트 판정 / 병렬 묶음 2개 통합 / 결정으로 진행할 WP 없음 중 먼저 오는 지점에서 끝난다. W1/W2 통합이 먼저 끝나면 WP-11은 다음 RUN에 남긴다. 종료 전 P-08로 HANDOFF를 갱신·커밋·푸시하고 최종 동일 HEAD CI를 확인한다. 기록은 .orchestrator/app-threads.json과 보존 M0 registry를 대조한다.
